# День 1: Анатомия промпта — P.T.C.F. 🔬

**Трек:** 👨‍💻 Программист | **Время:** 25 минут

---

## 🎯 P.T.C.F. Модель

```
P - Persona (Роль)
T - Task (Задача)
C - Context (Контекст)
F - Format (Формат)
```

---

## 📋 Структура

### 1️⃣ Persona (Роль)

```markdown
Ты — Senior Python разработчик с 10+ годами опыта.
Специализация: чистый код, тестирование, архитектура.
```

**Когда использовать:**
- Нужен специфический стиль кода
- Важны best practices
- Нужен педагогический подход

### 2️⃣ Task (Задача)

```markdown
Напиши функцию для валидации email:
- Проверка формата
- Обработка edge cases
- Return bool
```

**Правила:**
- Конкретная, измеримая, однозначная
- Разбей на numbered list

### 3️⃣ Context (Контекст)

```markdown
- Это для production API
- Будет использоваться при регистрации
- High-load: миллионы запросов/день
- Python 3.10+, стандартная библиотека
```

### 4️⃣ Format (Формат)

```markdown
- Type hints для всех аргументов
- Docstring в Google формате
- Примеры использования
- Без внешних зависимостей
```

---

## 🛠️ Пример: Полный промпт

```markdown
## Persona
Ты — Senior Python разработчик, специализируешься на data validation.

## Task
Напиши функцию validate_email(email: str) -> bool

## Context
- Production API регистрации пользователей
- High-load: миллионы запросов/день
- Python 3.10+, только стандартная библиотека
- Отсеять явно невалидные email

## Format
- Type hints
- Google docstring
- 3-5 примеров в docstring
- Обработка edge cases
- Не выбрасывать exceptions, return False для невалидных
```

---

## 📊 Сравнение промптов

| Плохой промпт | Хороший промпт |
|---------------|----------------|
| "Напиши функцию" | "Напиши функцию X с Y требованиями" |
| "Сделай что-то с базой" | "Напиши PostgreSQL query для таблицы users" |
| "Исправь ошибку" | "Ошибка X в коде Y. Как исправить?" |
