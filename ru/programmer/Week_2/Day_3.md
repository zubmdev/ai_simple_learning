# День 3: Chain of Thought (CoT) 🧠

**Трек:** 👨‍💻 Программист | **Время:** 25 минут

---

## 💡 Идея

Сложную задачу агент должен решить в два прохода: **сначала план — потом код**. План ревьюится за минуту; ошибка в плане, пойманная до генерации, экономит целую итерацию.

```
❌ Без CoT: агент сразу пишет код → ты ревьюишь большой дифф → ошибка в подходе = всё заново
✅ С CoT: агент показывает план → ты правишь план → дифф по согласованному плану
```

---

## 🔬 Шаблон CoT промпта

```markdown
Задача: [описание + критерии приёмки]

Прежде чем писать код:
1. Какие подходы существуют для решения?
2. Какой подход оптимальный и почему?
3. Какие edge cases нужно учесть?
4. Какую архитектуру выбрать?

Покажи план и остановись. Код — после моего подтверждения.
```

💡 «Покажи план и остановись» — ключевая фраза. Без неё агент смешает план и код в одном ответе, и ты потеряешь точку контроля.

---

## 🛠️ Примеры

### Для алгоритмов

```
Задача: Найти кратчайший путь в графе. Готово, когда тесты на циклическом графе проходят.

Сначала план:
1. Какие алгоритмы существуют? (BFS, Dijkstra, A*, Bellman-Ford)
2. Какой подходит для невзвешенного графа и почему?
3. Опиши структуру данных и сложность
4. Какие edge cases (изолированная вершина, циклы)?
```

### Для делегирования рефакторинга

```
Код в src/legacy.py работает, но его страшно трогать.

Сначала покажи план рефакторинга:
1. Какие функции затронутся?
2. Порядок шагов, чтобы каждый шаг оставлял код рабочим?
3. Какие тесты нужны до начала?
4. Что может сломаться и как это заметить?
```

План «каждый шаг оставляет код рабочим» — это страховка: на любом шаге можно остановиться и откатиться.

### Для дебаггинга

```
Код падает с ошибкой: [вставь traceback]

Сначала гипотезы, без кода:
1. Что должен делать код?
2. Что происходит на самом деле?
3. В каком месте логика нарушена и почему?
4. Какой минимальный фикс?
```

---

## 📊 Когда использовать CoT

| Задача | CoT нужен? |
|--------|------------|
| Простой CRUD | ❌ Нет — избыточен |
| Сложный алгоритм | ✅ Да |
| Дебаггинг | ✅ Да |
| Рефакторинг с риском | ✅ Да — план = план отката |
| Архитектура | ✅ Да |
| Простой рефакторинг | ❌ Нет |

Проверка простоты: если задача решается одним диффом до ~30 строк — CoT не нужен.

---

## ✅ Верификация плана

План — не текст для чтения «по диагонали». Проверь:

1. **Покрывает ли план критерии приёмки?** Каждый пункт «готово, когда» должен быть виден в плане
2. **Есть ли шаг верификации?** Если в плане нет «как проверим» — верни план
3. **Обратим ли каждый шаг?** Для рискованных правок — есть ли точка отката

---

## 🎯 Миссия

Реши одну сложную задачу (алгоритм, рефакторинг или баг) через два прохода: план → подтверждение → код.

**Формат артефакта:** план агента + твоё подтверждение/правки + финальный дифф.

**Проверка:** в плане был пункт про верификацию; дифф соответствует согласованному плану; критерии приёмки выполнены.
