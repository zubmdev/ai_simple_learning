# День 4: AI Debugging 🐛

**Трек:** 👨‍💻 Программист | **Время:** 30 минут

---

## 🎯 Цель

Освоить debug-цикл с агентом: воспроизведение → спека бага → гипотеза → дифф → верификация тестом.

---

## 📋 Debug-цикл

```
1. Воспроизведи баг (тест или команда)
2. Опиши спеку бага агенту
3. Агент: гипотеза → план фикса
4. Diff review
5. Примени → прогони воспроизводящий тест
6. Тест зелёный? Готово. Красный? → шаг 2 с новой информацией
```

Правило: **нет воспроизведения — нет фикса.** Если баг нельзя показать тестом или командой, агент чинит гипотетическую проблему, а не твою.

---

## 📋 Структура спеки бага

```markdown
## Контекст
Что делает код: [кратко]
Что ожидаю: [ожидаемое поведение]
Что получаю: [фактическое поведение]

## Воспроизведение
pytest tests/test_api.py::test_parse_empty_response
# → падает, вывод прилагаю

## Ошибка
[Полный traceback]

## Что пробовал
1. [попытка 1 и её результат]

## Окружение
- Python: 3.11
- OS: Ubuntu 22.04
- Библиотеки: [versions]

## Как действуешь
Сначала гипотеза и план, без правок. Потом diff фикса + тест,
который падал до фикса и проходит после.
```

Агент в Cline сам видит файлы и может запустить тест — попроси его сделать это и показать вывод.

---

## ❌ Плохой промпт

```
Не работает. Помоги.
```

Нет воспроизведения, нет ожиданий, нет критерия готовности. Агент будет угадывать.

---

## ✅ Хороший промпт

````markdown
## Контекст
Парсю JSON из API и сохраняю в базу.
Ожидаю: словарь с данными
Получаю: JSONDecodeError

## Ошибка
```
json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0)
```

## Код
```python
import requests
response = requests.get('https://api.example.com/data')
data = json.loads(response.text)
```

## Что пробовал
1. Проверил URL в браузере — возвращает JSON
2. print(response.text) — пустая строка

Готово, когда: тест на пустой ответ API проходит, а на валидном JSON данные сохраняются.
Сначала гипотеза, потом diff.
````

---

## 🔧 Продвинутые техники

### 1. AI Code Review (до запуска)

```
Проверь diff на:
- Security vulnerabilities
- Race conditions
- Обработку ошибок

Верни JSON: [{file, line, severity, problem, fix}].
Без изменений кода, только отчёт.
```

Отчёт в JSON — не прозу: его можно прогнать по чек-листу ревью.

### 2. Root Cause Analysis

```
Код работал вчера, сегодня упал. Изменения: [что менял / git log -3]

Проанализируй:
1. Какие из этих изменений могли вызвать ошибку?
2. Какие зависимости обновились?
3. Как найти root cause за минимальное число запусков?
```

### 3. Test Case Generation (двойная проверка фикса)

```
Код должен обрабатывать: пустой ввод, None, неверный формат, Unicode, очень длинные строки.

Напиши pytest тесты для функции [файл/имя].
Готово, когда: pytest проходит, и среди тестов есть тот, что падал до фикса.
```

Тесты пишет агент — но критерии кейсов задаёшь ты.

---

## 💡 Diff review при дебаге

Фикс агента ревьюится строже обычного: дебаг-диффы вносят правки «на повторе», и лишние изменения легко проскакивают.

- [ ] Дифф содержит **только** фикс, без попутного рефакторинга?
- [ ] Каждый hunk можно объяснить через гипотезу из шага 3?
- [ ] Воспроизводящий тест добавлен/обновлён?
- [ ] Ничего не удалено «заодно»?
