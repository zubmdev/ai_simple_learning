**Трек:** 👨‍💻 Программист | **Время:** 25 минут

## 🎯 Миссия

Получить от агента карту незнакомого кода и сохранить её в файл. Артефакт:
`notes/repo-map.md` с точками входа, слоями и зависимостями — и твой
контрольный вопрос, на который агент отвечает по этой карте.

---

## 💡 Кто читает репозиторий

```text
Вариант 1: ты читаешь сам и поставляешь файлы агенту
Вариант 2: агент исследует сам (grep, glob, чтение), ты направляешь
```

Агент читает код быстро, но без направления ходит кругами. Твоя роль —
диспетчер: сузить область, задать порядок, остановить, когда ответы
перестали добавлять новое.

**Аналогия:** экскурсовод в музее. Гид (агент) знает залы, но маршрут
задаёшь ты — иначе он водит толпу по кругу.

### Когда что выбирать

```text
Свой проект, знаешь структуру → подай файлы явно (День 2)
Чужой/legacy, не знаешь с чего начать → ориентационный проход агентом
Гигантский репозиторий → сузь область: папка или маска файлов
```

## 🧠 Ориентационный проход

Шаг 1 — карта без чтения файлов целиком:

```text
Составь карту репозитория. Правила:
1. Сначала структура папок (ls/glob), не читай файлы целиком.
2. Найди точки входа и конфиги.
3. Определи слои и направления зависимостей.
4. Ответ — в 5–7 пунктах, каждый с путями файлов.
```

Шаг 2 — только после карты углубляйся в выбранный модуль:

```text
Теперь модуль src/services. Прочитай файлы модуля и
объясни: ответственность, зависимости, точки расширения.
```

Шаг 3 — сохрани карту в `notes/repo-map.md` и попроси агента дополнить
её при следующих находках. Это постоянная память о проекте (подробно —
Неделя 4, День 3).

## 🛠️ Практика: разбор legacy-кода

**1. Создай запутанный файл:**

```bash
mkdir legacy-tour && cd legacy-tour
```

```python
# legacy.py
import json
from pathlib import Path
from typing import Any

class P:
    def __init__(self, s: str):
        self.s = Path(s)
        self._c: dict[str, Any] = {}

    def l(self) -> dict:
        if self.s.name in self._c:
            return self._c[self.s.name]
        with open(self.s, 'r') as f:
            d = json.load(f)
        self._c[self.s.name] = d
        return d

    def t(self, d: dict, k: list[str]) -> list[dict]:
        return [{x: d[x]} for x in k if x in d]

    def s(self, d: list[dict], o: str) -> None:
        with open(o, 'w') as f:
            json.dump(d, f, indent=2)

if __name__ == '__main__':
    p = P('data.json')
    d = p.l()
    t = p.t(d, ['name', 'email'])
    p.s(t, 'out.json')
```

**2. Ориентационный промпт (агент читает сам, ничего не прикладываем):**

```text
Прочитай legacy.py и объясни:
1. Что делает класс P?
2. Что означают методы l, t, s?
3. Какие проблемы в коде?
Предложи читаемые названия. Отвечай кратко.
```

**3. Проверка понимания — задай вопрос, ответа на который в промпте не было:**

```text
Что произойдёт, если data.json битый? А если его нет?
```

Агент должен ответить, опираясь на код (`json.load` бросит исключение) —
это признак, что он реально читал файл, а не выдумывает.

**4. Рефакторинг:**

```text
Отрефактори legacy.py:
1. Переименуй класс и методы
2. Добавь docstrings
3. Улучши type hints
После правки покажи diff и прогони: python legacy.py
```

## 💡 Pro Tips

```text
❌ "Объясни код"
✅ "Что делает функция X? Какие edge cases обрабатывает?"
```

- Инкрементально: карта → модуль → файл. Не проси всё сразу.
- Каждый ответ проверяй встречным вопросом по коду — так ловятся
  галлюцинации на раннем этапе.
- Находки фиксируй в `notes/repo-map.md`, а не держи в чате.
