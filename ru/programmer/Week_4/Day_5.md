## 🎯 Миссия

Настроить права агента по принципу наименьших привилегий и получить
доказательства, что они работают. Артефакт: конфиг с правами + два
зафиксированных случая — агент запросил одобрение на запись и был
остановлен на запрещённой команде.

---

## 💡 Наименьшие привилегии

Агенту нужны права на задачу, а не на всё. По умолчанию — спросить;
исключения — только для безопасных, предсказуемых команд.

```text
Чтение и поиск:     можно без спроса — это не риск
Запись файлов:      одобрение на каждый diff
Команды:            по белому списку; деплой и git push — никогда сами
Секреты:            агент не видит .env и не получает ключи в промптах
```

**Аналогия:** стажёру дают доступ к репозиторию на чтение, а не к прод-серверу.

## 🛠️ Настройка прав

### OpenCode: `opencode.json` в корне проекта

```json
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "ask",
    "webfetch": "ask",
    "bash": {
      "*": "ask",
      "python -m pytest": "allow",
      "git status": "allow",
      "git push": "deny",
      "rm -rf *": "deny"
    }
  }
}
```

Значения: `allow` — без спроса, `ask` — каждое использование с одобрением,
`deny` — запрет. Начни с `ask` везде и открывай `allow` только тому, что
проверил руками.

### Cline: авто-одобрения

В настройках Cline найди блок Auto-approve: выключи авто-одобрение записи
файлов и выполнения команд, оставь чтение. Задай лимит последовательных
действий — агент остановится и спросит, а не уедет в цикле.

🚨 Точные названия переключателей меняются между версиями — сверься с
доками, если блок называется иначе. Принцип стабилен: запись и команды —
только с одобрения.

## 🛠️ Практика: полный цикл с правами

**1. Возьми проект** из прошлых дней (`blog-api` / `todo-cli`) с `AGENTS.md`
(День 1) и журналом `DECISIONS.md` (День 3).

**2. Настрой права** по образцу выше. В `.env` положи фиктивную переменную
`API_KEY=pretend-secret` и убедись: задача не заставляет агента читать этот
файл — если попросит, это повод для `deny` и разбора.

**3. Задача в три шага — проверь каждое право:**

```text
Добавь в проект функцию stats(): количество задач по категориям.
По правилам проекта. Тест и прогон обязательны. Не коммить.
```

| Шаг | Что должно произойти | ✅ |
|-----|----------------------|----|
| Агент пишет файл | Запросил одобрение на запись (edit: ask) | |
| Агент гоняет тесты | `pytest` прошёл без вопроса (allow) | |
| Ты просишь `git push` | Агент остановлен deny-правилом | |

**4. Найди запрет в действии.** Попроси агента «опубликовать изменения» —
он должен попытаться, упереться в `git push: deny` и сообщить об этом.
Сделай скриншот/запиши сообщение — это часть артефакта.

**5. Зафиксируй решение** (День 3 — постоянная память):

```text
Зафиксируй в DECISIONS.md: права проекта — edit ask,
pytest allow, git push deny. Причина: diff-ревью обязательное.
```

**6. Прогон через скилл (День 2):** вызови `add-endpoint` в новой сессии и
посмотри, сколько раз агент запросил одобрение. Шесть подтверждений на
пять шагов — норма; ноль — повод перепроверить конфиг.
