# День 1: Vibe Coding — смена парадигмы 🧠

**Трек:** 👨‍💻 Программист | **Время:** 15 минут

---

## 💡 Главная идея

**Традиционный подход:**
```
Ты → думаешь → пишешь код → дебажишь → рефакторишь
```

**Vibe Coding:**
```
Ты → описываешь задачу → агент генерирует → ты ревьюишь дифф → проверяешь → итерируешь
```

---

## 🎯 Почему это работает

| Аспект | Традиционный | Vibe Coding |
|--------|--------------|-------------|
| Фокус | Синтаксис и детали | Архитектура и логика |
| Время на boilerplate | Высокое | Минимальное |
| Качество кода | Зависит от опыта | Спека + твой diff review + тесты |
| Обучение | syntax-first | context-first |

---

## 🔑 Ключевые принципы

### 1. Ты — архитектор, не каменщик

```
❌ Старое мышление:
"Напишу REST API с нуля. Начну с роутинга, потом модели..."

✅ Vibe Coding:
"Создай REST API для блога с CRUD операциями на FastAPI.
Включи валидацию, обработку ошибок, Swagger документацию.
Готово, когда: эндпоинты отвечают 200/422, тесты проходят."
```

### 2. Контекст важнее синтаксиса

Агент знает синтаксис лучше тебя. Твоя задача — дать правильный контекст:
- Для чего этот код?
- Какие ограничения?
- Как проверить, что готово?

### 3. Делегирование с проверкой, а не вера

```
Спека → агент генерирует дифф → ты ревьюишь дифф → запускаешь тест → итерация
```

Агент производит диффы, не истину. Каждый дифф проходит через твой review.

## 📊 Сравнение: Cline vs OpenCode vs Cursor vs Copilot

| Критерий | Cline | OpenCode | Cursor | Copilot |
|----------|-------|----------|--------|---------|
| Open Source | ✅ Да | ✅ Да | ❌ Нет | ❌ Нет |
| Цена | 🆓 Бесплатно (свой API-ключ) | 🆓 Бесплатно (свой API-ключ) | 💰 $20/мес | 💰 $10/мес |
| Модели | 🔧 Любые | 🔧 Любые | 🔒 Через их серверы | 🔒 GitHub |
| Оффлайн | ✅ С Ollama | ✅ С Ollama | ❌ Нет | ❌ Нет |
| Приватность | 🔒 Ключ и код у тебя | 🔒 Ключ и код у тебя | ⚠️ Через их серверы | ⚠️ GitHub |

**Выбор курса:** **Cline** — базовый агент внутри VS Code. **OpenCode** — CLI-апгрейд для программиста: ставишь во День 2, когда захочешь работать из терминала. Это апгрейд, а не обязательная замена.

## ⚡ Мифы vs Реальность

| Миф | Реальность |
|-----|------------|
| "AI заменит программистов" | AI усиливает: ты всё ещё отвечаешь за архитектуру и ревью |
| "Код будет хуже" | Код зависит от качества спеки и твоей проверки |
| "Это только для простых задач" | Агенты справляются со сложными системами — если делить работу на шаги |
| "Не нужно знать программирование" | Нужно знать **больше** — архитектуру, паттерны, code review |

## 🛠️ Что изменилось в workflow

**Было:**
```python
# 1. Пишешь код вручную
# 2. Ищешь документацию
# 3. Дебажишь 2 часа
# 4. Рефакторишь
```

**Стало:**
```python
# 1. Пишешь спеку с критериями готовности
# 2. Агент генерирует дифф
# 3. Ты делаешь diff review
# 4. Проверяешь: тесты/запуск
# 5. Итерируешь через промпты
```

---

## 📝 Практика (5 минут)

Возьми одну задачу из твоей текущей работы и перепиши её как промпт-спеку:

```markdown
Задача: парсер CSV файла data.csv

Требования:
- Обработка ошибок (файл не существует, неверный формат)
- Пропуск пустых строк
- Возврат списка словарей
- Type hints, docstring в Google формате

Готово, когда:
- Скрипт запускается на битом файле и не падает
- На корректном файле возвращает ожидаемый список
```

Ты пока не запускаешь агента — только формулируешь. Завтра появится инструмент.

## 🎯 Миссия

Напиши одну спеку для задачи из твоего реального проекта.

**Формат артефакта:** файл `spec.md` (или заметка) с тремя секциями: задача, требования, критерии готовности (минимум 3 пункта «готово, когда...»).

**Проверка:** в спеке есть измеримые критерии готовности, и другой человек мог бы по ней проверить результат без вопросов к тебе.
