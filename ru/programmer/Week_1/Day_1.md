# День 1: Vibe Coding — смена парадигмы 🧠

**Трек:** 👨‍💻 Программист | **Время:** 15 минут

---

## 💡 Главная идея

**Традиционный подход:**
```
Ты → думаешь → пишешь код → дебажишь → рефакторишь
```

**Vibe Coding:**
```
Ты → описываешь задачу → AI генерирует → ты проверяешь → итерируешь
```

---

## 🎯 Почему это работает

| Аспект | Традиционный | Vibe Coding |
|--------|--------------|-------------|
| Фокус | Синтаксис и детали | Архитектура и логика |
| Время на boilerplate | Высокое | Минимальное |
| Качество кода | Зависит от опыта | AI + твой code review |
| Обучение | syntax-first | context-first |

---

## 🔑 Ключевые принципы

### 1. Ты — архитектор, не каменщик

```
❌ Старое мышление:
"Напишу REST API с нуля. Начну с роутинга, потом модели..."

✅ Vibe Coding:
"Создай REST API для блога с CRUD операциями на FastAPI.
Включи валидацию, обработку ошибок, Swagger документацию."
```

### 2. Контекст важнее синтаксиса

AI знает синтаксис лучше тебя. Твоя задача — дать правильный контекст:
- Для чего этот код?
- Какие ограничения?
- Какой стиль?

### 3. Итеративный подход

```
Промпт 1: "Базовая версия"
Промпт 2: "Добавь обработку ошибок"
Промпт 3: "Оптимизируй производительность"
Промпт 4: "Добавь тесты"
```

---

## ⚡ Мифы vs Реальность

| Миф | Реальность |
|-----|------------|
| "AI заменит программистов" | AI усиливает, не заменяет |
| "Код будет хуже" | Код зависит от твоих промптов |
| "Это только для простых задач" | AI справляется со сложными системами |
| "Не нужно знать программирование" | Нужно знать **больше** — архитектуру, паттерны, code review |

---

## 🛠️ Что изменилось в workflow

**Было:**
```python
# 1. Пишешь код вручную
# 2. Ищешь документацию
# 3. Дебажишь 2 часа
# 4. Рефакторишь
```

**Стало:**
```python
# 1. Пишешь промпт
# 2. AI генерирует код
# 3. Ты делаешь code review
# 4. Итерируешь через промпты
```

Попробуй изменить мышление на реальной задаче:

```

Требования:
- Обработка ошибок (файл не существует, неверный формат)

- Type hints
- Docstring в Google формате"
```
