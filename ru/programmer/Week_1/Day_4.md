## 🎯 Цель дня

Освоить agent loop: спека → делегирование → diff review → верификация → итерация.

---

## 📋 Agent Loop

```
1. Спека → 2. Делегирование агенту → 3. Diff review → 4. Верификация → 5. Итерация или готово
```

Разница с чат-ботом: агент не просто отвечает текстом — он правит файлы и запускает команды. Поэтому цикл замыкается твоей проверкой, а не «выглядит правдоподобно».

---

## 🔬 Анатомия промпта-спеки

### Компоненты

```markdown
## Роль
Ты — Senior Python разработчик, специализируешься на чистом коде.

## Задача
Напиши функцию для валидации email.

## Контекст
- Это для API регистрации
- Нужно отсеять невалидные email
- Используй только стандартную библиотеку

## Требования
1. Type hints
2. Docstring (Google format)
3. Handle edge cases
4. Return bool

## Готово, когда
- Невалидные входы возвращают False, а не бросают исключение
- Есть тесты: валидный, пустой, None, без домена
- Тесты проходят
```

### Минимальный промпт

```
Напиши Python функцию validate_email(email: str) -> bool
с валидацией формата, docstring и 4 pytest-тестами.
```

## 🔄 Итеративное делегирование

### Паттерн: Базовая версия → Улучшения

```
Итерация 1:
"Создай REST API для блога на FastAPI с CRUD. Покажи дифф до применения."

Итерация 2:
"Добавь валидацию Pydantic для всех endpoints"

Итерация 3:
"Добавь обработку ошибок и логирование"

Итерация 4:
"Напиши unit тесты с pytest и запусти их"
```

### Почему маленькие шаги работают

| Подход | Результат |
|--------|-----------|
| Один большой промпт | Большой дифф, который лень ревьюить — пропустишь ошибку |
| Маленькие итерации | Каждый дифф читается за минуту, ошибка ловится сразу |

## 🧠 Продвинутые техники

### Plan-first (сначала план, потом код)

```
Прежде чем писать код:
1. Какие паттерны применимы?
2. Какие edge cases нужно учесть?
3. Какую архитектуру выбрать?

Покажи план и жди моего подтверждения.
```

План ревьюить дешевле, чем код. Ошибка в плане = вся генерация насмарку.

### Few-shot (примеры)

```
Напиши функцию в таком стиле:

def get_user_by_id(user_id: int) -> User | None:
    """Получает пользователя по ID."""
    return db.query(User).filter_by(id=user_id).first()

Теперь напиши функцию get_user_by_email(email: str) -> User | None
```

### Diff review как ритуал

```
Прежде чем применять изменения:
1. Покажи diff
2. Объясни каждую правку одной строкой
3. Отметь файлы, которые не должен был трогать, если такие появились
```

Ревьюишь как pull request от джуна: сомнительное — отклоняешь.

## 🛠️ Практика: создаём игру "Угадай число" через агента

### Итерация 1: Базовая версия (спека)

```markdown
Создай игру "Угадай число" на Python:
- Компьютер загадывает 1-100
- Пользователь угадывает
- Подсказки: больше/меньше

Готово, когда: игра запускается, корректное число завершает цикл с поздравлением.
```

### Итерация 2: Обработка ошибок

```
Добавь:
- Обработку ввода не-чисел
- Команду exit для выхода
- Подсчёт попыток

Готово, когда: ввод "abc" не роняет игру.
```

### Итерация 3: Улучшения

```
Добавь:
- Выбор сложности (1-50, 1-100, 1-500)
- ASCII-арт приветствие
- Сохранение рекорда в файл

Готово, когда: рекорд перезаписывается при лучшем результате.
```

Каждая итерация: дифф → ревью → запуск. Не accepting дифф «на веру».

## 💡 Best Practices

### ✅ DO

```
✅ "Напиши функцию X с type hints и docstring. Готово, когда тесты проходят"
✅ "Обработай edge cases: пустой ввод, None, неверный формат"
✅ "Покажи diff перед применением"
✅ "Запусти тесты и покажи вывод"
```

### ❌ DON'T

```
❌ "Сделай что-нибудь с базой данных" (нет критериев готовности)
❌ "Напиши код" (слишком общее)
❌ "Исправь это" (без контекста ошибки)
❌ Принять большой дифф без чтения
```

## 🐛 Дебаггинг через агента

### Структура промпта

```markdown
**Ошибка:** [вставь полный traceback]

**Что ожидаю:** [ожидаемое поведение]

**Что получил:** [фактическое поведение]

**Что уже пробовал:**
1. [попытка 1]

**Как действуешь:** сначала гипотеза и план, потом фикс. Фикс не применять — показать diff.
```

Агент в Cline видит файлы проекта сам — не копируй весь код, указывай файл и функцию.

## 🎯 Миссия

Прогони полный agent loop на маленькой функции из твоего проекта.

**Шаги:**
1. Напиши спеку с секцией «Готово, когда» (минимум 2 критерия)
2. Делегируй агенту в Cline с просьбой показать diff
3. Сделай diff review: прочитай каждую правку
4. Верифицируй: запусти код или тесты

**Формат артефакта:** спека + применённый дифф + результат запуска (вывод теста/скрипта).

**Проверка:** все критерии «Готово, когда» выполнены, и ты можешь объяснить каждую строку диффа.
