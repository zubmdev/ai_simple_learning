## Часть 1: Проблема "быстрых" ответов

### Что происходит обычно?

Когда ты просишь ИИ написать код, он часто сразу выдаёт результат.

**Пример:**

```
Промпт: Напиши алгоритм поиска кратчайшего пути в графе.
```

**ИИ:** *сразу пишет код*

**Проблема:** ИИ может:
- Выбрать неоптимальный алгоритм
- Не учесть edge cases
- Написать код с логическими ошибками
- Не объяснить выбор решения

### Почему это происходит?

LLM (Large Language Models) работают по принципу "предсказание следующего токена". Без явного указания, они могут дать первый попавшийся ответ.

---

## Часть 2: Что такое Chain of Thought?

### Определение

**Chain of Thought (CoT)** — это техника, при которой ты явно просишь ИИ:
1. **Проанализировать** задачу
2. **Рассуждать** пошагово
3. **Объяснить** логику
4. **Только потом** написать код

### Простая фраза, которая меняет всё

Добавь в любой промпт:

```
Думай пошагово (step-by-step).
```

Или:

```
Сначала проанализируй задачу, потом напиши код.
```

## Анализ задачи

### 1. Существующие алгоритмы

Для поиска кратчайшего пути в графе существуют:

- **BFS (Breadth-First Search)** — для невзвешенных графов, O(V + E)
- **Dijkstra** — для взвешенных графов с неотрицательными весами, O((V + E) log V)
- **Bellman-Ford** — для графов с отрицательными весами, O(V * E)
- **Floyd-Warshall** — для всех пар вершин, O(V³)
- **A*** — с эвристикой, быстрее Dijkstra в некоторых случаях

### 2. Сравнение

| Алгоритм | Сложность | Когда использовать |
|----------|-----------|-------------------|
| BFS | O(V + E) | Невзвешенный граф, кратчайший путь |
| Dijkstra | O((V+E) log V) | Взвешенный, без отрицательных весов |
| Bellman-Ford | O(V * E) | Отрицательные веса |

### 3. Выбор алгоритма

Для **невзвешенного графа** оптимальный выбор — **BFS**:
- Простая реализация
- Оптимальная сложность O(V + E)
- Гарантирует кратчайший путь

### 4. Логика работы BFS

1. Начинаем с начальной вершины
2. Добавляем её в очередь
3. Пока очередь не пуста:
   - Берём вершину из очереди
   - Для каждого соседа:
     - Если не посещён — добавляем в очередь
     - Запоминаем расстояние
4. Возвращаем расстояние до целевой вершины

### 5. Псевдокод

```
function BFS(graph, start, end):
    queue = [(start, 0)]
    visited = {start}
    
    while queue not empty:
        node, distance = queue.pop(0)
        
        if node == end:
            return distance
        
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append((neighbor, distance + 1))
    
    return -1  // Путь не найден
```

### 6. Python код

```python
from collections import deque
from typing import Dict, List, Optional

def find_shortest_path(
    graph: Dict[str, List[str]], 
    start: str, 
    end: str
) -> Optional[int]:
    """
    Находит кратчайший путь в невзвешенном графе с помощью BFS.
    
    Args:
        graph: Словарь {вершина: [соседи]}
        start: Начальная вершина
        end: Целевая вершина
        
    Returns:
        Длина кратчайшего пути или None если путь не найден
        
    Examples:
        >>> graph = {'A': ['B', 'C'], 'B': ['D'], 'C': ['D'], 'D': []}
        >>> find_shortest_path(graph, 'A', 'D')
        2
    """
    if start == end:
        return 0
    
    # Очередь для BFS: (вершина, расстояние)
    queue = deque([(start, 0)])
    visited = {start}
    
    while queue:
        node, distance = queue.popleft()
        
        # Проверяем всех соседей
        for neighbor in graph.get(node, []):
            if neighbor == end:
                return distance + 1
            
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append((neighbor, distance + 1))
    
    return None  # Путь не найден
```
```

### Пример 2: Дебаггинг с CoT

#### Без CoT

```
Этот код не работает. Исправь.

def calculate_average(numbers):
    total = 0
    for n in numbers:
        total += n
    return total / len(numbers)
```

**ИИ:** *сразу исправляет, возможно неправильно*

#### С CoT

```
Проанализируй этот код пошагово:

1. Что должен делать этот код? (опиши ожидаемое поведение)
2. Какие входные данные ожидаются?
3. Какие edge cases могут быть?
4. В каком месте логика нарушается?
5. Почему это происходит?
6. Как это исправить?
7. Напиши исправленный код

Код:
def calculate_average(numbers):
    total = 0
    for n in numbers:
        total += n
    return total / len(numbers)
```

**ИИ:**

```
## Анализ кода

### 1. Что должен делать код?
Функция должна вычислять среднее арифметическое списка чисел.

### 2. Ожидаемые входные данные
- Список чисел (int или float)
- Список может быть пустым или содержать элементы

### 3. Возможные edge cases
1. **Пустой список** → `len(numbers) = 0` → DivisionByZero
2. **None вместо списка** → TypeError
3. **Список с None** → TypeError при сложении
4. **Список со строками** → TypeError
5. **Очень большой список** → overflow (редко)

### 4. Где нарушается логика?
**Проблема:** Строка `return total / len(numbers)`

При пустом списке:
- `len(numbers) = 0`
- Деление на 0 → ZeroDivisionError

### 5. Почему это происходит?
Нет проверки на пустой список перед делением.

### 6. Как исправить?
1. Добавить проверку `if not numbers`
2. Вернуть 0 или None для пустого списка
3. Добавить type hints
4. Добавить docstring

### 7. Исправленный код

```python
from typing import List, Optional, Union

def calculate_average(
    numbers: List[Union[int, float]]
) -> Optional[float]:
    """
    Вычисляет среднее арифметическое списка чисел.
    
    Args:
        numbers: Список чисел
        
    Returns:
        Среднее арифметическое или None для пустого списка
        
    Examples:
        >>> calculate_average([1, 2, 3, 4, 5])
        3.0
        >>> calculate_average([])
        None
    """
    if not numbers:
        return None
    
    total = sum(numbers)
    return total / len(numbers)
```

### Тесты

```python
assert calculate_average([1, 2, 3, 4, 5]) == 3.0
assert calculate_average([10]) == 10.0
assert calculate_average([]) is None
assert calculate_average([0, 0, 0]) == 0.0
```
```

**Разница:** CoT помогает найти **все** проблемы, а не только очевидную.

Проанализируй проблему пошагово:

3. Какие edge cases?

## Анализ требований к паролю

### 1. Стандартные требования

| Требование | Критичность | Почему |
|------------|-------------|--------|
| Минимальная длина (8+) | Критично | Защита от брутфорса |
| Максимум длина (128) | Опционально | Предотвращение DoS |
| Минимум 1 заглавная | Рекомендуется | Увеличивает энтропию |
| Минимум 1 строчная | Рекомендуется | Увеличивает энтропию |
| Минимум 1 цифра | Рекомендуется | Увеличивает энтропию |
| Минимум 1 спецсимвол | Рекомендуется | Увеличивает энтропию |
| Нет пробелов | Опционально | Совместимость |
| Нет последовательностей | Опционально | "123", "abc" |

### 2. Выбор требований

Реализуем:
- ✅ Минимум 8 символов
- ✅ Минимум 1 заглавная
- ✅ Минимум 1 строчная
- ✅ Минимум 1 цифра
- ✅ Минимум 1 спецсимвол

### 3. Проверка каждого требования

```python
import re

def validate_password(password: str) -> tuple[bool, list[str]]:
    """
    Валидирует пароль по требованиям безопасности.
    
    Требования:
    - Минимум 8 символов
    - Минимум 1 заглавная буква
    - Минимум 1 строчная буква
    - Минимум 1 цифра
    - Минимум 1 спецсимвол
    
    Args:
        password: Пароль для проверки
        
    Returns:
        (is_valid, errors) — валиден ли пароль и список ошибок
        
    Examples:
        >>> validate_password("Weak")
        (False, ['Пароль слишком короткий', 'Нет цифр', ...])
        >>> validate_password("StrongP@ss123")
        (True, [])
    """
    errors = []
    
    # Проверка длины
    if len(password) < 8:
        errors.append("Пароль должен быть минимум 8 символов")
    
    # Проверка заглавных букв
    if not re.search(r'[A-Z]', password):
        errors.append("Пароль должен содержать минимум 1 заглавную букву")
    
    # Проверка строчных букв
    if not re.search(r'[a-z]', password):
        errors.append("Пароль должен содержать минимум 1 строчную букву")
    
    # Проверка цифр
    if not re.search(r'\d', password):
        errors.append("Пароль должен содержать минимум 1 цифру")
    
    # Проверка спецсимволов
    if not re.search(r'[!@#$%^&*(),.?":{}|<>]', password):
        errors.append("Пароль должен содержать минимум 1 спецсимвол")
    
    return (len(errors) == 0, errors)
```

### 4. Тесты

## Часть 7: Когда НЕ нужен CoT?

CoT избыточен для:

| Задача | Почему CoT не нужен |
|--------|---------------------|
| "Hello World" | Слишком простая задача |
| Функция `sum(a, b)` | Тривиальная задача |
| Установка библиотеки | Стандартная процедура |
| Простой SQL запрос | Однозначное решение |

**Правило:** Если задача понятна с первого промпта — CoT не нужен.
