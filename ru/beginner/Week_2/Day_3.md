## 🚨 Быстрый ответ без плана

```text
Промпт: напиши алгоритм поиска кратчайшего пути в графе
```

Модель сразу выдаёт код и может:
- выбрать неоптимальный алгоритм
- пропустить edge cases
- написать код с логической ошибкой

Проблему ты замечаешь после запуска — и переделываешь. Дороже, чем согласовать план заранее.

**Аналогия:** подрядчик без сметы: «начали стройку — вышло не то и дороже». Смета до стройки = план до кода.

---

## 💡 Chain of Thought: план, который можно проверить

**CoT** — просьба к модели рассуждать пошагово и показать план до кода.

Минимальная фраза:

```text
Сначала покажи план, жди моего подтверждения, потом пиши код.
```

Сильная форма — потребовать критерии к каждому пункту:

```text
Прежде чем писать код:
1. Перечисли требования из спецификации
2. Составь план: какой шаг какой критерий закрывает
3. Покажи план и жди подтверждения
```

Так план становится черновиком чеклиста приёмки: «шаг 2 закрывает критерий 3». После кода ты проверяешь именно критерии, а не «вроде нормально».

---

## 🛠️ Практика: валидатор пароля через план

Спецификация: функция `validate_password(password: str) -> tuple[bool, list[str]]` — возвращает, валиден ли пароль, и список нарушенных требований.

### Шаг 1: Попроси план

```text
Задача: validate_password по требованиям:
- минимум 8 символов
- минимум 1 заглавная, 1 строчная, 1 цифра, 1 спецсимвол
- возвращает (is_valid, errors): errors — список нарушенных требований

Сначала покажи план: какие проверки и в каком порядке, какой критерий закрывает каждая.
Жди подтверждения. Код — только после него.
```

### Шаг 2: Проверь план, а не код

Хороший план выглядит так:

| Проверка | Критерий |
|----------|----------|
| длина меньше 8 | validate_password("Abc1!")[1] содержит «символов» |
| нет заглавной | validate_password("abc1!xyz")[0] is False |
| нет цифры | validate_password("Abc!xyz")[0] is False |
| всё корректно | validate_password("Strong1!Pass") == (True, []) |

Видишь дыру — скажи агенту до кода: «добавь обработку пустой строки».

### Шаг 3: Подтверди и прими работу

После подтверждения агент пишет код. Принимай по критериям — сохрани их в `check_password.py`:

```python
from password_validator import validate_password

assert validate_password("Strong1!Pass") == (True, [])
assert validate_password("Abc1!")[1], "Должна быть ошибка про длину"
assert validate_password("nouppercase1!")[0] is False
assert validate_password("")[1], "Пустая строка должна дать ошибку"

print("Все проверки пройдены")
```

```text
python check_password.py
```

План проверил логику до кода, скрипт — код после. Два барьера вместо одного.

## 🧠 Шаблоны плана

Для новой функции:

```text
Сначала план, потом код:
1. Требования из спецификации списком
2. План: шаг → какой критерий он закрывает
3. Жди подтверждения
4. После кода: как проверить каждый критерий
```

Для исправления:

```text
Прежде чем править:
1. Что происходит сейчас и что должно происходить
2. Где именно ломается
3. План исправления и как я проверю результат
Жди подтверждения.
```

**Когда CoT не нужен:** «Hello World», сложение двух чисел, установка библиотеки. Если задача понятна с первого промпта и есть критерий — план лишний. CoT — инструмент для задач, где легко выбрать не тот подход.

## 🎯 Миссия дня

План-до-кода для сортировки списка объектов по нескольким полям.

1. Опиши агенту задачу: `sort_items(items, key_fields)` — сортирует список словарей по полям по порядку (например, сначала name, потом age). Запроси план с критериями по шаблону из практики.
2. Согласуй план (поправь, если пункт нельзя проверить) и сохрани его в `plan_sort.md`.
3. После подтверждения агент пишет `sort_items.py`. Проверь:

```python
from sort_items import sort_items

items = [
    {"name": "b", "age": 2},
    {"name": "a", "age": 3},
    {"name": "a", "age": 1},
]
result = sort_items(items, ["name", "age"])
assert result == [
    {"name": "a", "age": 1},
    {"name": "a", "age": 3},
    {"name": "b", "age": 2},
], f"Неверный порядок: {result}"

print("Все проверки пройдены")
```

**Артефакт дня:** `plan_sort.md` (план + критерии) и зелёный `python check_sort.py`. Если пункт плана нельзя проверить — это не план, а пожелание.
