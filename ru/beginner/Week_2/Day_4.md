# День 4: Искусство дебаггинга через промпты 🐛

**Трек:** 🌱 Начинающий | **Время:** 50 минут

Ошибки — это нормально. Проблема не в ошибке, а в репорте «не работает, помоги»: по нему агент чинит наугад. Сегодня ты научишься писать баг-репорт как спецификацию ошибки — с ожиданием, фактом и критерием «починено» — и закрывать баги циклом «делегируй → дифф → проверка».

---

## 🎯 Цель дня

Научиться описывать ошибки так, чтобы агент чинил с первого-второго раза, и принимать починку по критерию.

**Ты научишься:**
- Собирать баг-репорт: ожидание, факт, traceback, окружение
- Формулировать критерий «баг закрыт»
- Работать в Cline циклом: репорт → дифф → проверка → уточнение

---

## 🚨 Как НЕ надо

```text
Не работает. Помоги.
```

```text
У меня ошибка, исправь.
```

```text
Код падает, не знаю почему.
```

Во всех трёх агенту не хватает того же, чего не хватает спецификации без критерия: ожидания, факта и способа проверки. Останется гадать — и агент будет гадать вместе с тобой.

---

## 💡 Баг-репорт = мини-спецификация ошибки

**Настрой:** ошибка — это не провал, а входные данные для следующего шага. Разница между «3 часа паники» и «5 минут починки» — в репорте.

| Элемент | Пример |
|---------|--------|
| ✅ Что делает код | «Парсю JSON из API» |
| ✅ Что ожидаю | «Словарь с пользователями» |
| ✅ Что получаю | «JSONDecodeError» |
| ✅ Полный traceback | Скопируй целиком, без сокращений |
| ✅ Релевантный код | Проблемное место, не весь файл |
| ✅ Окружение | Python 3.11, requests 2.31, Windows 11 |
| ✅ Критерий «починено» | «python app.py печатает имена и завершается с кодом 0» |

Критерий «починено» — самый важный пункт. Без него «исправлено» — это мнение агента, а не проверяемый факт.

### Шаблон баг-репорта

```text
Дебаггинг Python-кода.

Что делает: [одна фраза о функциональности]
Ожидаю: [ожидаемое поведение]
Получаю: [фактическое поведение]

Traceback:
[полный текст ошибки]

Код:
[проблемная часть]

Окружение: Python [версия], [библиотека и версия], [ОС]

Критерий «починено»: [команда] завершается без ошибок / тесты проходят.

Найди причину, предложи план, жди подтверждения. Трогай только [файл].
```

Сохрани шаблон в заметки: он переиспользуется в каждом баге.

---

## 🛠️ Практика 1: упавший парсер JSON

### Плохой репорт

```text
JSONDecodeError, помоги.
```

### Хороший репорт

```text
Дебаггинг Python-кода.

Что делает: скачиваю пользователей из API и парсю JSON.
Ожидаю: словарь с данными, печатаю имена.
Получаю: JSONDecodeError при парсинге ответа.

Traceback:
Traceback (most recent call last):
  File "app.py", line 15, in <module>
    data = json.loads(response.text)
json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0)

Код:
response = requests.get("https://api.example.com/users")
data = json.loads(response.text)

Окружение: Python 3.11, requests 2.31, Windows 11

Критерий «починено»: python app.py печатает имена и завершается с кодом 0.
```

### Цикл в Cline

1. Отправь репорт. Агент предложит план — проверь его (вчерашний навык).
2. После правки посмотри дифф: агент должен был добавить проверку `status_code` и заменить `json.loads(response.text)` на `response.json()` — а не переписать весь файл.
3. Запусти критерий:

```text
python app.py
```

4. Если снова падает — не переписывай репорт с нуля, ответь новым фактом:

```text
Критерий не пройден: теперь ConnectionError при таймауте.
Traceback: [новый traceback]
Файл app.py не переписывай, правь только функцию fetch.
```

Каждая итерация сужает круг: репорт → дифф → проверка → факт → репорт.

## 🛠️ Практика 2: логическая ошибка

Код запускается, но результат неверный — и баг заметил пользователь, потому что тестов не было.

```python
def calculate_discount(price, discount_percent):
    """Вычисляет цену со скидкой."""
    return price - (price * discount_percent)

print(calculate_discount(100, 20))  # -1900, а ждали 80
```

Репорт с критерием:

```text
Дебаггинг логической ошибки.

Ожидаю: calculate_discount(100, 20) == 80.0 (скидка 20%).
Получаю: -1900.

Критерий «починено»:
- calculate_discount(100, 20) == 80.0
- calculate_discount(100, 0) == 100.0
- calculate_discount(100, 150) вызывает ValueError
```

Здесь критерий приёмки — готовые assert-ы: отдай их агенту как тесты, которые должны пройти. Починка без зелёных проверок не принимается.

## 💡 Превентивный дебаггинг: ревью до запуска

Код можно проверить до запуска — как спецификацию до кода:

```text
Просмотри calculate_discount против спецификации:
1. Найди расхождения кода с критериями
2. Перечисли edge cases, которые не покрыты
3. Для каждого: пример входа и что произойдёт
Код пока не меняй.
```

Агент нашёл проблему в тексте — ты починил её до первого запуска. Самый дешёвый баг — тот, что не дошёл до запуска.

## 🎯 Миссия дня

Баг с полным циклом закрытия.

1. Возьми код с ошибкой (деление на ноль на пустом списке — классика):

```python
def calculate_average(numbers):
    total = 0
    for n in numbers:
        total += n
    return total / len(numbers)
```

2. Напиши `bugreport.md` по шаблону: что делает, что ожидаешь, что получаешь (запусти с пустым списком и скопируй traceback), критерий «починено»: пустой список → `None`, обычные случаи считают среднее.
3. Делегируй репорт в Cline, посмотри дифф.
4. Проверь:

```python
from average import calculate_average

assert calculate_average([1, 2, 3, 4, 5]) == 3.0
assert calculate_average([10]) == 10.0
assert calculate_average([]) is None
assert calculate_average([0, 0, 0]) == 0.0

print("Все проверки пройдены")
```

**Артефакт дня:** `bugreport.md`, исправленный `average.py` и зелёный `python check_average.py`. Если чинил больше двух итераций — нормально: каждая итерация сужала репорт.
