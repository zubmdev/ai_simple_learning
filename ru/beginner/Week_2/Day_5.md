## 🛠️ Шаг 1: Спецификация с критериями приёмки

Исходный скрипт (из Недели 1):

```python
from art import tprint

def main():
    print("=== ASCII Арт Генератор ===")
    name = input("Введите ваше имя: ").strip()
    while not name:
        name = input("Имя не может быть пустым! Попробуйте снова: ").strip()
    tprint(name, font="block")

if __name__ == "__main__":
    main()
```

Чего в нём нет: выбора стиля, сохранения в файл, обработки Ctrl+C, тестов. Напиши `spec_ascii.md` по шаблону из Дня 1 — с критериями, описанными **поведением**, а не словами «удобно» и «красиво»:

```text
## Задача
Улучши ascii_art.py (код ниже), сохранив текущее поведение.

## Требования
1. Валидация имени: 1–50 символов
2. Выбор стиля: block, standard, slant, banner (номером)
3. Сохранение результата в ascii_result.txt по запросу
4. Ctrl+C — корректное завершение без traceback

## Критерии приёмки
- [ ] пустое имя → повторный запрос ввода
- [ ] имя «Max», стиль 1 → арт напечатан
- [ ] ответ «да» на сохранение → ascii_result.txt создан и не пуст
- [ ] Ctrl+C в любой момент → программа завершается без traceback
- [ ] python -m pytest test_ascii.py -v — все тесты зелёные
```

Теперь результат можно проверить, а не обсудить.

## 🛠️ Шаг 2: Few-shot для стиля

Покажи агенту, какой код считается «твоим» (День 2):

```text
Пример стиля проекта:

def save_to_file(content: str, filepath: str) -> bool:
    """Сохраняет контент в файл."""
    try:
        with open(filepath, "w") as f:
            f.write(content)
        return True
    except IOError as e:
        print(f"Ошибка: {e}")
        return False

Весь новый код — в этом стиле: type hints, docstring Google, обработка ошибок.
```

## 🛠️ Шаг 3: План до кода

```text
Сначала план: какие функции выделишь, какой критерий приёмки закрывает каждая.
Жди подтверждения. Код — после него.
```

Проверь план по чеклисту: каждая строка ссылается на критерий из `spec_ascii.md`? Пустое имя покрыто? Ctrl+C покрыт? Править план дешевле, чем код.

---

## 🛠️ Шаг 4: Делегирование и дифф

Подтверди план — агент пишет код. Перед сохранением посмотри дифф в Cline:

- тронуты только файлы из плана?
- нет «попутных» изменений, которых не было в спецификации?
- стиль — как в Few-shot примере?

Лишние изменения — повод вернуть задачу: «критерий X не требовал менять Y, откати».

---

## 🛠️ Шаг 5: Проверка и уточнение

Прогони критерии вручную:

```text
python ascii_art.py
```

Сценарий: пустой ввод → повтор; «Max» + стиль 1 → арт; «да» → файл создан. Затем автопроверка — тесты попроси у агента по критериям:

```text
Напиши test_ascii.py на pytest по критериям из spec_ascii.md:
validate_name, выбор стиля, сохранение в файл.
```

```text
python -m pytest test_ascii.py -v
```

Критерий упал — верни агенту факт, а не мнение:

```text
Критерий «Ctrl+C без traceback» не пройден: в консоли стек-трейс KeyboardInterrupt.
Правь только обработку прерывания. Покажи дифф.
```

Цикл повторяется, пока все критерии не станут зелёными. Это и есть приёмка.
