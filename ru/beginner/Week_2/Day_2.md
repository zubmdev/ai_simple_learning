## 🚨 Zero-shot: задача без образцов

**Zero-shot** — ты описываешь задачу словами, без примеров. Модель опирается на общие знания.

```text
Напиши функцию, которая преобразует JSON в XML.
```

| Ситуация | Подходит? |
|----------|-----------|
| Стандартная задача | ✅ Да |
| Форма результата не важна | ✅ Да |
| Нужен быстрый черновик | ✅ Да |
| Нужен стиль твоего проекта | ❌ Нет |
| Нужна точная форма вывода | ❌ Нет |

Zero-shot — это не «проверять не надо». Критерий приёмки остаётся в промпте всегда, меняется только способ его формулировки.

---

## 💡 Few-shot: примеры как часть спецификации

**Few-shot** — ты показываешь 1–3 примера желаемого результата перед задачей. Примеры задают **форму**: стиль docstring, обработку ошибок, type hints. Модель копирует паттерн.

```text
Вот пример функции из моего проекта:

def read_file(path: str) -> str:
    """Читает файл и возвращает содержимое."""
    import logging
    logging.info(f"Reading file: {path}")
    with open(path, "r") as f:
        content = f.read()
    logging.info(f"Successfully read {len(content)} chars")
    return content

Напиши write_file(path: str, content: str) в том же стиле.
Критерий приёмки: есть логирование до и после записи, type hints, docstring.
```

**Сколько примеров нужно:**

| Количество | Когда |
|------------|-------|
| 1 пример | Показать стиль |
| 2–3 примера | Показать вариации паттерна |
| 4 и больше | Признак того, что задачу надо разбить на подзадачи |

## 🛠️ Практика: одна задача, два подхода

Задача для Cline: функция `get_users()` — получить список пользователей из API.

### Вариант A: Zero-shot

```text
Напиши функцию get_users: GET https://api.example.com/users, верни список.
```

Типичный результат — три строки кода: без обработки ошибок, без timeout, без docstring. Работает ровно до первого сбоя API.

### Вариант B: Few-shot

```text
Напиши get_users() в стиле моего проекта. Пример:

def get_posts() -> list[dict]:
    """Получает все посты из API."""
    import requests
    try:
        response = requests.get("https://api.example.com/posts", timeout=10)
        response.raise_for_status()
        return response.json()
    except requests.RequestException as e:
        raise requests.RequestException(f"Failed to fetch posts: {e}")

Критерий приёмки — форма функции:
- [ ] type hints у возврата
- [ ] docstring
- [ ] timeout=10
- [ ] raise_for_status()
- [ ] перехват requests.RequestException
```

### Проверка формы

Чеклист формы — это тоже критерий приёмки. Проверь его по диффу в Cline: каждый пункт либо есть, либо функция возвращается агенту на доработку.

Структурированные результаты проверяются автоматически. Попроси агента:

```text
Проверь email "user@example.com" и верни результат строго как JSON без текста вокруг:
{"valid": true|false, "reasons": ["..."]}
```

И проверь форму скриптом:

```python
import json

data = json.load(open("result.json"))
assert set(data) == {"valid", "reasons"}, f"Неверные ключи: {set(data)}"
assert isinstance(data["reasons"], list)
print("Форма JSON корректна")
```

Форма проверяется так же, как поведение: скрипт плюс зелёный вывод.

---

## 🧠 Три правила хороших примеров

1. **Реальные, не выдуманные.** Пример из твоего `utils.py` лучше схемы «из головы»: модель копирует то, что видит.
2. **Разнообразные.** Три одинаковых примера задают шаблон хуже, чем один read + один write + один delete.
3. **Полные.** Обрезанная функция «def process_data(data): ...» учит модель обрезать ответ.

## 🎯 Миссия дня

Few-shot-спецификация для загрузчика TOML-конфигов.

1. В проекте есть `load_json_config`. Создай `spec_toml.md`: пример ниже + задача «напиши load_toml_config(path: str) -> dict в том же стиле» + критерий приёмки.

```python
def load_json_config(path: str) -> dict:
    """Загружает JSON конфигурацию."""
    import json, logging
    logging.info(f"Loading config from {path}")
    with open(path, "r") as f:
        return json.load(f)
```

2. Делегируй `spec_toml.md` в Cline, посмотри дифф перед сохранением.
3. Создай `config.toml`:

```toml
debug = true
name = "course"
```

4. Проверь форму и поведение:

```python
from config_loader import load_toml_config

cfg = load_toml_config("config.toml")
assert isinstance(cfg, dict), "Должен вернуть словарь"
assert cfg.get("debug") is True, "Должен прочитать debug"
print("Все проверки пройдены")
```

**Артефакт дня:** `spec_toml.md`, `config_loader.py` с функцией `load_toml_config` и зелёный вывод проверки в терминале.
