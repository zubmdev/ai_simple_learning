## Часть 1: Проблема чужого кода

### Типичная ситуация

```text
Ты открыл проект:
- 50 файлов
- Странные названия функций
- Никаких комментариев
- Код 3-летней давности

Вопрос: "Что это вообще делает?! 😱"
```

### Старый подход vs Vibe Coding

| Старый подход | Vibe Coding |
|---------------|-------------|
| Читать каждый файл | Попросить агента объяснить |
| Гуглить каждую функцию | Спросить агента |
| Тратить часы | Тратить минуты |
| Разочарование | Понимание |

Но есть условие: агент объяснит код ровно настолько хорошо, насколько правильный контекст ты ему дал. Чужой код — идеальный полигон для навыков Дней 1–2.

## Часть 2: Магический промпт

```text
@<файл с кодом>

Объясни мне этот код так, будто мне 10 лет.
Не используй технический жаргон.

Ответь:
1. Что делает код в целом?
2. Какие в нём основные функции?
3. Как данные проходят через код?
4. Какие библиотеки используются и зачем?
```

### Почему это работает

```text
✅ "как 10-летнему" → агент упрощает объяснение
✅ "без жаргона" → агент избегает сложных терминов
✅ Структурированный запрос → структурированный ответ
✅ Файл прикреплён через @ → агент смотрит именно на него
```

## Часть 3: 🛠️ Практика — разбираем незнакомый код

### Задание: понять Python-скрипт

**Шаг 1:** Создай файл `mystery_code.py` — представь, что ты его не писал:

```python
import json
from pathlib import Path
from typing import Any

class DataProcessor:
    def __init__(self, source: str):
        self.source = Path(source)
        self._cache: dict[str, Any] = {}

    def load(self) -> dict:
        if self.source.name in self._cache:
            return self._cache[self.source.name]

        with open(self.source, 'r') as f:
            data = json.load(f)

        self._cache[self.source.name] = data
        return data

    def transform(self, data: dict, keys: list[str]) -> list[dict]:
        result = []
        for key in keys:
            if key in data:
                result.append({key: data[key]})
        return result

    def save(self, data: list[dict], output: str) -> None:
        with open(output, 'w') as f:
            json.dump(data, f, indent=2)

if __name__ == '__main__':
    processor = DataProcessor('input.json')
    data = processor.load()
    transformed = processor.transform(data, ['name', 'email'])
    processor.save(transformed, 'output.json')
```

**Шаг 2:** В Cline прикрепи файл через @ и напиши:

```text
@mystery_code.py

Объясни мне этот код так, будто мне 10 лет.
Не используй технический жаргон.

Ответь:
1. Что делает этот код в целом?
2. Что такое DataProcessor?
3. Что делают load, transform и save?
4. Зачем нужен _cache?
```

**Шаг 3:** Прочитай объяснение и проверь себя

Ты должен понять:
- Класс — это «коробка» с кнопками (функциями)
- `load` — загружает данные из файла
- `transform` — вытаскивает только нужные поля
- `save` — сохраняет результат
- `_cache` — запоминает, чтобы не читать файл дважды

Если что-то осталось непонятным — задай уточняющий вопрос тем же чатом: контекст уже загружен.

## Часть 4: Продвинутые промпты

### Промпт 1: Найти проблемы в коде

```text
@mystery_code.py

Найди в коде:
1. Потенциальные ошибки
2. Места, где код может упасть
3. Неэффективные места

Объясни каждую проблему простыми словами.
```

### Промпт 2: Понять зависимости

```text
@main.py
@models.py
@config.py

Объясни:
1. Какие файлы зависят друг от друга?
2. Какие библиотеки используются?
3. Как данные передаются между файлами?
4. Какая точка входа в программу?
```

### Промпт 3: Найти, где что происходит

```text
@src

Где в проекте происходит:
- Авторизация пользователя
- Подключение к базе данных
- Обработка ошибок

Укажи файлы и номера строк.
```

💡 Папка `@src` в последнем промпте — это много токенов. Для большого проекта сузь запрос до подпапки: `@src/auth`, а не весь `@src`.

## Часть 5: Чужой проект с GitHub

### Задание: разобрать маленький проект

**Шаг 1:** Найди маленький проект (до ~20 файлов) — например, CLI-утилиту или простую игру на Python. Скачай и открой:

```bash
git clone <ссылка-на-проект>
cd <папка-проекта>
code .
```

**Шаг 2:** Сначала — карта, потом детали. В Cline напиши:

```text
Покажи структуру проекта: какие папки и файлы есть?
Одобри команду просмотра, если агент её предложит.
```

**Шаг 3:** Теперь попроси объяснить главные файлы:

```text
Какие 2–3 файла здесь главные? Прикрепи их себе и объясни
проект по ним:
1. Что он делает?
2. Как его запустить?
3. Как пользоваться как пользователь?
```

Так ты не тащишь весь проект в контекст — сначала карта, потом только главное.

## Часть 6: Типичные ошибки

### ❌ Ошибка 1: Не давать контекст

```text
Промпт: "Объясни код"

Агент: "Какой код? Я не вижу файлов."
```

**Решение:** назови файл в тексте задачи или прикрепи через @.

### ❌ Ошибка 2: Давать слишком много

```text
@<папка на 100 файлов>

Агент: *обрабатывает 5 минут* "Слишком много информации, уточни запрос"
```

**Решение:** прикрепляй только нужную подпапку или 2–3 файла.

### ❌ Ошибка 3: Слишком общий вопрос

```text
Промпт: "Что это?"

Агент: "Что именно? Уточни вопрос."
```

**Решение:** задавай конкретные вопросы из магического промпта.
