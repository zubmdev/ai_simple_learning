# День 1: Context is King — бюджет контекста 👑

**Трек:** 🌱 Начинающий | **Время:** 35 минут

---

## 🎯 Цель дня

Понять, что такое контекст, из чего состоит его бюджет — и почему качество ответа агента зависит от того, что ты в этот бюджет положил.

---

## Часть 1: Что такое контекст?

### Простая аналогия

Представь, что ИИ — это **умный помощник**, который:
- Знает все языки программирования
- Знает все библиотеки и фреймворки
- Но **НЕ ЗНАЕТ твой проект**

Когда ты просишь: «Напиши функцию для моего проекта», ИИ спрашивает:
- Какой язык? Какой фреймворк?
- Какая база данных?
- Какой стиль кода?
- Какие есть файлы?

**Контекст** — это ответы на эти вопросы: всё, что агент «видит» в момент работы над задачей.

---

## Часть 2: Бюджет контекста

### 🎒 Аналогия: рюкзак

Окно контекста — это рюкзак, который агент берёт в поход. Всё, что ты туда положишь, ему придётся нести всю задачу:

- Положил мало → в нужный момент нечего надеть (агент не понимает задачу)
- Набросал всё подряд → рюкзак тяжёлый, идёшь медленно (ответ хуже, дольше и дороже)
- Собрался правильно → только то, что нужно на маршрут

Бюджет измеряется в **токенах** — кусочках текста по несколько символов. Файл на 200 строк — это тысячи токенов. У каждой модели окно конечное, а на бесплатных API есть ещё дневные лимиты токенов: раздутый контекст сжигает квоту на будущее.

### Три вопроса перед каждой задачей

```text
1. Что агенту ВАЖНО знать для этой задачи?   → берём
2. Сколько места это займёт?                 → считаем
3. Что точно можно выбросить?                → выбрасываем
```

## Часть 3: Пример без контекста и с контекстом

### ❌ Без контекста

```text
Промпт: Напиши функцию для получения пользователей

Результат ИИ:
def get_users():
    # общий код без понимания твоего проекта
    pass
```

Агент дал **общий ответ**, потому что не знает твой проект.

### ✅ С контекстом

```text
Промпт: Напиши функцию для получения пользователей.

Контекст:
- Проект: FastAPI REST API
- База: PostgreSQL с SQLAlchemy
- Модель: User(id, email, name, created_at)
- Стиль: async/await, type hints

Результат ИИ:
async def get_users(db: AsyncSession) -> list[User]:
    """Получает всех пользователей из базы."""
    result = await db.execute(select(User))
    return result.scalars().all()
```

Агент дал **точный ответ**, потому что получил правильный контекст.

## Часть 4: Context Bloat — когда рюкзак переполнен

**Context Bloat** — это когда ты даёшь агенту слишком много информации.

```text
❌ Пример Context Bloat:
"Вот весь мой проект из 150 файлов.
Исправь ошибку в файле main.py на строке 42."

Агент получает:
- 150 файлов (5MB текста)
- Тратит бюджет на "чтение" всего
- Теряет фокус на важном
- Ответ хуже или медленнее
```

### Почему это плохо?

| Проблема | Объяснение |
|----------|------------|
| ⏱️ Медленно | Агент обрабатывает каждый токен |
| 💰 Дорого | API тарифицирует токены, бесплатные лимиты тают |
| 🧠 Путается | Слишком много информации |
| 📉 Качество | Агент теряет фокус |

## Часть 5: Правило трёх файлов

Для большинства задач достаточно:

1. **Файл, который правишь** (например, `main.py`)
2. **Файл с зависимостями** (например, `models.py`)
3. **Файл конфигурации**, если важен (например, `config.py`)

### Пример

```text
Задача: Добавить новое поле email в модель User

Нужный контекст:
✅ models.py (где модель User)
✅ migrations/ (если используешь миграции)

НЕ нужный контекст:
❌ tests/ (не нужно для изменения модели)
❌ frontend/ (не связано с backend)
❌ docs/ (документация не нужна)
❌ .git/ (история не нужна)
```

## Часть 6: 🛠️ Практика — определи нужный контекст

### Задание 1

**Задача:** Изменить цвет кнопки «Купить» на красный.

**Какой контекст нужен?**

```text
✅ Файл с компонентом кнопки (Button.jsx)
✅ Файл стилей (Button.css или styled-components)
❌ База данных (не связана)
❌ API endpoints (не связано)
❌ Backend код (не связано)
```

### Задание 2

**Задача:** Добавить новое поле `phone` в профиль пользователя.

**Какой контекст нужен?**

```text
✅ models/user.py (модель User)
✅ api/users.py (endpoint для профиля)
✅ schemas/user.py (если есть Pydantic schemas)
❌ Frontend компоненты (не нужно для backend)
❌ Тесты (можно добавить потом)
```

### Задание 3

**Задача:** Исправить баг: при загрузке изображения падает с ошибкой «File too large».

**Какой контекст нужен?**

```text
✅ Файл с загрузкой изображений (upload.py)
✅ Конфигурация (config.py — лимиты размера)
✅ Middleware/валидация (если есть проверки)
❌ CSS стили (не связано)
❌ HTML шаблоны (не связано с ошибкой)
```

## Часть 7: Как дать контекст в Cline

Всё ниже работает на любом уровне:

| Уровень | Железо / доступ | Модель |
|---------|------------------|--------|
| 1 | CPU + бесплатный API (Groq) | `openai/gpt-oss-20b` |
| 2 | 4GB GPU + Ollama | `qwen3.5:2b` |
| 3 | 16GB GPU + Ollama | `gpt-oss:20b` |

*Проверено: 2026-10-24*

В Cline контекст не появляется сам собой. Три способа, которые мы освоим на этой неделе:

```text
1. Назови файлы путями прямо в тексте задачи:
   "В файле todo.py добавь..."
2. Прикрепи файл или папку через @-упоминание в поле задачи
3. Вставь ошибку или лог из терминала прямо в задачу
```

## 🧠 Ключевые принципы

| Принцип | Объяснение |
|---------|------------|
| **Context is King** | Качество ответа зависит от качества контекста |
| **Бюджет конечен** | Окно контекста и лимиты API не резиновые |
| **Не всё подряд** | Не давай весь проект — дай 1–3 нужных файла |
| **Думай за агента** | Спроси себя: «Что нужно знать, чтобы решить задачу?» |

## 🎯 Миссия дня

**Артефакт:** файл `context-plan.md` — план контекста для трёх задач твоего проекта.

```text
1. Возьми свой проект (или придумай будущий).
2. Запиши 3 типичные задачи для него.
```
