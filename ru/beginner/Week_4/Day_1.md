**Трек:** 🌱 Начинающий | **Время:** 30 минут

---

## 🎯 Цель дня

Понять, что такое RAG (Retrieval-Augmented Generation) на простом примере.

---

## Часть 1: Проблема

### Ситуация

У тебя есть проект:
- 100 файлов
- 50,000 строк кода
- Сложная структура

Ты спрашиваешь ИИ:

```
"Где в проекте происходит авторизация?"
```

### Без RAG

```
ИИ: "Я не знаю. Дай мне файлы."
Ты: *добавляешь 100 файлов вручную*
ИИ: *обрабатывает 5 минут*
ИИ: "В файле auth.py строка 42"
```

### С RAG

```
ИИ: "Сейчас посмотрю..."
ИИ: *автоматически ищет по проекту*
ИИ: "В файле auth.py строка 42"
```

---

## Часть 2: Аналогия — ИИ-библиотекарь

### Представь библиотеку

```
📚 Библиотека = твой проект
👤 Ты = задаёшь вопрос
🤖 ИИ-библиотекарь = RAG система

Без библиотекаря:
Ты: "Где книга про Python?"
Библиотекарь: "Не знаю, поищи сам на полках."
Ты: *бродишь по библиотеке 2 часа*

С библиотекарем:
Ты: "Где книга про Python?"
Библиотекарь: *смотрит в каталог*
Библиотекарь: "Полка 3, ряд 2, книга 'Python for Beginners'"
```

### Как работает RAG

```
1. Ты задаёшь вопрос
2. RAG ищет в "каталоге" (индексе) проекта
3. RAG находит релевантные куски кода
4. RAG даёт эти куски ИИ
5. ИИ отвечает на основе найденного
```

---

## Часть 3: Техническое объяснение (простое)

### Шаг 1: Индексация

```
Когда ты открываешь проект в VS Code:
1. Continue.dev сканирует все файлы
2. Создаёт "индекс" — как каталог в библиотеке
3. Индекс хранит:
   - Содержимое файлов
   - Где какие функции
   - Связи между файлами
```

### Шаг 2: Поиск (Retrieval)

```
Когда ты пишешь @Codebase:

1. ИИ берёт твой вопрос
2. Превращает в "вектор" (числа)
3. Сравнивает с векторами в индексе
4. Находит топ-N похожих кусков
5. Отдаёт их ИИ как контекст
```

### Шаг 3: Генерация (Generation)

```
ИИ получает:
- Твой вопрос
- Найденные куски кода

ИИ генерирует ответ на основе:
- Своих знаний (обучение)
- Контекста из проекта (RAG)
```

## Часть 4: RAG vs @Files vs @Folder

| Метод | Когда использовать | Как работает |
|-------|-------------------|--------------|
| `@Files` | Знаешь конкретные файлы | Ручное добавление |
| `@Folder` | Знаешь нужную папку | Ручное добавление папки |
| `@Codebase` | Не знаешь, где код | Автоматический поиск |

### Примеры

#### Пример 1: Известный файл

```
Задача: Изменить функцию в auth.py

✅ @Files: auth.py
   (быстро, точно)

❌ @Codebase
   (медленнее, избыточно)
```

#### Пример 2: Неизвестное место

```
Задача: Где происходит отправка email?

❌ @Files: ???
   (не знаю, какой файл)

✅ @Codebase
   (ИИ сам найдёт)
```

#### Пример 3: Понимание архитектуры

```
Задача: Как работает вся система авторизации?

✅ @Codebase
   (ИИ найдёт все связанные файлы)
```

## Часть 5: Практика — первый опыт с RAG

### Подготовка проекта

**Шаг 1:** Создай тестовый проект

```bash
mkdir rag-test
cd rag-test
```

**Шаг 2:** Создай несколько файлов

`main.py`:
```python
from auth import login, logout
from database import get_user
from email_service import send_email

def main():
    user = login("admin", "password")
    if user:
        send_email(user.email, "Welcome!")
    logout()

if __name__ == "__main__":
    main()
```

`auth.py`:
```python
from database import get_user

def login(username, password):
    user = get_user(username)
    if user and user.password == password:
        return user
    return None

def logout():
    print("Logged out")
```

`database.py`:
```python
users = {
    "admin": {"email": "admin@example.com", "password": "password"}
}

def get_user(username):
    return users.get(username)
```

`email_service.py`:
```python
def send_email(to, subject):
    print(f"Sending email to {to}: {subject}")
```

### Использование @Codebase

**Шаг 1:** Открой проект в VS Code

```bash
code .
```

**Шаг 2:** Подожди индексации (30-60 секунд)

**Шаг 3:** В Continue напиши:

```

1. Какие модули?
2. Как они взаимодействуют?
3. Какой flow данных?
4. Где точка входа?
```

**Шаг 4:** Попробуй поиск

```

```

## Часть 6: Преимущества и ограничения RAG

### ✅ Преимущества

| Преимущество | Объяснение |
|--------------|------------|
| Автоматический поиск | Не нужно знать, где код |
| Понимание проекта | ИИ "видит" весь код |
| Связи между файлами | RAG находит зависимости |
| Экономия времени | Не добавляешь файлы вручную |

### ⚠️ Ограничения

| Ограничение | Объяснение |
|-------------|------------|
| Требует индексации | Первая загрузка дольше |
| Точность не 100% | Может найти не то |
| Локальные модели медленнее | Ollama обрабатывает на CPU/GPU |
| Большие проекты | 1000+ файлов = долгий поиск |

---

## Часть 7: Сравнение локальных vs облачных моделей для RAG

| Критерий | Ollama (локально) | Groq/Gemini (облако) |
|----------|-------------------|----------------------|
| Скорость RAG | 🐢 Медленнее | ⚡ Быстрее |
| Приватность | 🔒 Полная | ⚠️ Данные в облаке |
| Стоимость | 🆓 Бесплатно | 🆓/💰 Зависит от API |
| Размер проекта | Малый-средний | Любой |

**Совет:**
- До 50 файлов — Ollama отлично работает
- 50-200 файлов — Ollama работает, но медленнее
- 200+ файлов — Рассмотри API (Groq) для RAG
