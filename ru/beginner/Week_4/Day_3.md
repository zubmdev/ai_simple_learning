# День 3: Память агента — сессия и постоянные заметки 🧠

**Трек:** 🌱 Начинающий | **Время:** 35 минут

---

## 🎯 Цель дня

Различать два вида памяти агента и завести постоянную память проекта — файл заметок, который ты курируешь сам.

---

## Часть 1: Проблема — агент ничего не помнит

### Ситуация

Вчера вы с агентом выбрали хранение задач в JSON и добавили команду `stats`. Сегодня открываешь новый чат:

```text
Ты: "Добавь фильтр по категориям, как мы договорились вчера."
Агент: "Уточни, пожалуйста: о каких категориях речь?
        Я не знаю контекста прошлого разговора."
```

Агент не забыл тебя. У него просто нет памяти между сессиями — и это нормально.

---

## Часть 2: Аналогия — фрилансер-консультант

```text
Сессия = один рабочий день консультанта.
В течение дня он помнит всё, что вы обсудили.

Назавтра он приходит с чистой головой.
Помнит он только то, что записал в проектную документацию.

Кто отвечает за документацию? Не консультант. Заказчик.
То есть ты.
```

### Два вида памяти

| | Память сессии | Постоянная память |
|--|---------------|-------------------|
| Где | Текущий чат | Файлы в репозитории |
| Живёт | Пока открыт чат | Пока не удалишь |
| Кто ведёт | Агент сам | Ты курируешь |
| Для чего | Итерации внутри задачи | Решения, договорённости, причины |

Правила (`AGENTS.md`) — тоже постоянная память, но про «как работать». Сегодняшние заметки — про «что мы решили и почему».

---

## Часть 3: Практика — заводим память проекта

### 🛠️ Уровни доступа

Заметки — обычные файлы, работает на любом уровне:

| Уровень | Железо / доступ | Модель |
|---------|------------------|--------|
| 1 | CPU + бесплатный API (Groq) | `openai/gpt-oss-20b` |
| 2 | 4GB GPU + Ollama | `qwen3.5:2b` |
| 3 | 16GB GPU + Ollama | `gpt-oss:20b` |

*Проверено: 2026-10-24*

**Шаг 1:** Убедись на своём опыте, что сессия умирает. Открой **новый** чат и спроси:

```text
Какую команду мы добавили вчера и где хранятся задачи?
```

Агент не знает. Это твоя точка «до».

**Шаг 2:** Создай журнал решений `docs/decisions.md`:

```markdown
# Решения проекта

Формат: дата — решение — почему.

## 2026-10-26
- Задачи храним в JSON-файлах в папке todos/.
- Почему: ноль зависимостей, данные видно глазами, легко бэкапить.

## 2026-10-26
- Категории: work, personal, shopping, other (по умолчанию other).
- Почему: четыре хватит для личного списка, больше — путаница.
```

**Шаг 3:** Подключи журнал к правилам. Добавь в `AGENTS.md` раздел:

```markdown
## Память проекта
Перед изменениями прочитай docs/decisions.md.
После важного решения (хранение данных, библиотека, структура)
добавь туда запись: дата, решение, почему.
```

**Шаг 4:** Проверь в новом чате:

```text
Прочитай docs/decisions.md и добавь фильтр: команда
"list <category>" показывает задачи только одной категории.
```

Теперь агент знает про категории и JSON — ты не пересказывал ни слова.

## Часть 4: Что стоит записывать, а что нет

### ✅ Записываем в decisions.md

```text
✅ Выбрали технологию и почему (отвергнутые варианты — тоже)
✅ Договорённости о структуре и формате данных
✅ Причины отказа от решения ("сделали на sync, async не нужен")
✅ Ссылки на важные для проекта внешние документы
```

### ❌ Не записываем

```text
❌ Каждый коммит и каждую мелочь — журнал превратится в шум
❌ Правила поведения — их место в AGENTS.md
❌ Секреты и ключи — никогда, только .env
❌ Пересказы разговоров — только выводы
```

💡 Память курируешь ты, а не агент: агент может предложить запись, но решаешь, оставаться ей или нет, ты. Раз в неделю пробегай журнал и вычёркивай устаревшее — память проекта должна быть короче, чем история чатов.

🚨 Если заметок станет много: в большом проекте агенту помогает поиск по репозиторию и внешней документации. Но база — короткий курируемый журнал, а не свалка всего подряд.

---

## Часть 5: Как понять, что память работает

```text
Тест новой сессии:
1. Закрой чат, открой новый.
2. Спроси: "Какое хранение задач мы выбрали и почему?"
3. Агент отвечает по docs/decisions.md, не переспрашивая = ✅
```

Второй тест: попроси агента добавить несуществующую категорию — правило «категории: work, personal, shopping, other» должно остановить его до изменения кода.

## 🎯 Миссия дня

**Артефакт:** `docs/decisions.md` с двумя записями + правило в `AGENTS.md` + пройденный тест новой сессии.

```text
1. Запиши в docs/decisions.md два реальных решения твоего проекта.
2. Добавь в AGENTS.md раздел "Память проекта".
3. В новом чате задай вопрос из Части 5 — агент должен
   ответить без переспрашивания.
```

Проверка: `git log --oneline -1` показывает коммит с журналом; скопируй ответ агента из нового чата и убедись, что в нём причина решения из твоей записи.
