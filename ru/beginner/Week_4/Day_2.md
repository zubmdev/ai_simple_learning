# День 2: Skills — плейбуки для повторяющихся задач 🛠️

**Трек:** 🌱 Начинающий | **Время:** 40 минут

---

## 🎯 Цель дня

Завести свой первый навык-плейбук: файл с пошаговым рецептом, по которому агент выполняет повторяющуюся задачу одинаково каждый раз.

---

## Часть 1: Проблема — задача повторяется, а промпт каждый раз новый

### Ситуация

Каждую неделю ты просишь агента об одном и том же:

```text
"Добавь команду в todo.py: найди main(), добавь функцию,
добавь ветку elif, обнови справку Commands, запусти и проверь"
```

Каждый раз — заново, и каждый раз агент что-то забывает.

### Решение: плейбук

```text
Записал рецепт ОДИН РАЗ в файл
→ дальше: "Следуй плейбуку playbooks/add-command.md,
   добавь команду stats"
→ агент выполняет по шагам, ничего не теряя
```

---

## Часть 2: Аналогия — чек-лист пилота

```text
Пилот не держит в голове порядок предполётной проверки.
Есть чек-лист: пункт за пунктом, каждый с проверкой.

Плейбук = чек-лист для агента:
- шаги по порядку
- у каждого шага — как проверить, что он сделан
- финальный прогон в конце
```

Правила (`AGENTS.md`) отвечают на вопрос «как работать всегда». Плейбук — «как выполнить вот этот тип задачи от начала до конца».

---

## Часть 3: Где живут skills в инструментах

Идея одна, названия разные:

| Инструмент | Где лежит | Как вызывается |
|------------|-----------|----------------|
| OpenCode | `.opencode/skills/<имя>/SKILL.md` | агент находит сам или по имени |
| Cline (workflows) | markdown-файл workflow | командой `/имя` из чата |
| Любой агент (универсально) | файл в репозитории, например `playbooks/*.md` | «Следуй плейбуку …» |

💡 Для курса мы используем универсальный путь — файл в репозитории. Он работает в любом агенте, его видно в git, и его легко править. Интерфейсы инструментов меняются, плейбук в репозитории — нет. (*Проверено: 2026-10-24*)

### Из чего состоит хороший плейбук

```text
1. Название и когда применять        → одна задача
2. Шаги с точными путями файлов      → агент не ищет вслепую
3. Проверка после каждого шага       → ошибка ловится сразу
4. Финальный прогон                  → задача закрыта проверкой
```

Плохой плейбук — «улучши код». Хороший — 5 шагов, каждый с командой проверки.

---

## Часть 4: Практика — создаём плейбук

### 🛠️ Уровни доступа

Плейбук — это текстовый файл, поэтому всё ниже работает на любом уровне:

| Уровень | Железо / доступ | Модель |
|---------|------------------|--------|
| 1 | CPU + бесплатный API (Groq) | `openai/gpt-oss-20b` |
| 2 | 4GB GPU + Ollama | `qwen3.5:2b` |
| 3 | 16GB GPU + Ollama | `gpt-oss:20b` |

*Проверено: 2026-10-24*

**Шаг 1:** В проекте из Недели 3 создай папку и файл `playbooks/add-command.md`:

```bash
mkdir playbooks
```

**Шаг 2:** Запиши в `playbooks/add-command.md`:

```markdown
# Плейбук: добавить команду в todo-cli

Применять, когда нужно добавить новую команду в todo.py.

## Шаг 1. Изучи точку входа
Открой todo.py, найди функцию main() и цикл обработки команд.
Понимай: каждая команда — ветка if/elif.

## Шаг 2. Напиши функцию
Добавь функцию с type hints и docstring рядом с другими функциями.
Не меняй существующие функции.

## Шаг 3. Подключи команду
Добавь ветку elif в main() для новой команды.
Обнови строку-справку Commands.

## Шаг 4. Проверь
Запусти: python todo.py
Выполни новую команду с тестовыми данными.
Команда считается готовой, только если вывод корректный.

## Запреты
- Не удаляй и не переименовывай существующие команды.
- Ничего не устанавливай без подтверждения.
```

**Шаг 3:** Закоммить плейбук — это часть твоей обвязки:

```bash
git add playbooks/add-command.md
git commit -m "Add add-command playbook"
```

**Шаг 4:** Вызови навык в чате агента:

```text
Следуй плейбуку playbooks/add-command.md
и добавь команду stats — она печатает, сколько задач
в каждой категории.
```

---

## Часть 5: Проверка — агент идёт по шагам

Следи за ответом агента и отмечай:

| Шаг плейбука | Агент сделал? | Проверка выполнена? | ✅/❌ |
|--------------|---------------|---------------------|-------|
| 1. Изучил main() | | | |
| 2. Функция с type hints | | | |
| 3. Ветка elif + справка | | | |
| 4. Запустил `python todo.py` | | | |

```bash
python todo.py
```

Выполни `stats` сам и убедись, что вывод корректный. Перед принятием дифа просмотри изменения: агент должен был тронуть только `todo.py`.

🚨 Если агент пропустил шаг плейбука — не исправляй молча. Скажи: «Ты пропустил шаг 4 плейбука. Выполни его». Так плейбук становится договором, а не пожеланием.

## Часть 6: Правила vs Плейбуки vs Память

| | Правила (`AGENTS.md`) | Плейбук (skill) | Память (День 3) |
|--|----------------------|-----------------|-----------------|
| Когда действует | В каждой задаче | Когда вызвал | Когда упомянул |
| Про что | Как работать | Как сделать тип задачи | Что уже решено |
| Пример | «Отвечай по-русски» | «Как добавить команду» | «Выбрали JSON-хранение» |

Один и тот же факт не должен жить во всех трёх местах. Правило — в правила, рецепт — в плейбук, принятое решение — в заметки (завтра).

## 🎯 Миссия дня

Проверка: `python todo.py` → команда `stats` выводит количество задач по категориям; `git log --oneline -2` показывает коммит плейбука.
