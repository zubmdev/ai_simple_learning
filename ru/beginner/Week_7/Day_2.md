## Часть 1: Что такое лог ошибки?

### Определение:

**Лог ошибки** — это сообщение, которое программа выводит, когда что-то идёт не так.

### Где искать логи?

```
1. Браузер (для веб-приложений):
   - Открой страницу
   - Нажми F12 (или Cmd+Option+I на Mac)
   - Перейди на вкладку "Console"
   - Красные сообщения = ошибки

2. Терминал (для backend/ботов):
   - Смотри в терминал, где запущена программа
   - Ищи красный текст или "Error", "Exception"

3. Файлы логов:
   - Часто в папке logs/ или в файле error.log
```

## Часть 2: Анатомия ошибки

### Типичное сообщение об ошибке:

```
Uncaught TypeError: Cannot read properties of null (reading 'value')
    at HTMLButtonElement.addTask (app.js:15:25)
    at HTMLFormElement.onsubmit (index.html:12:35)
```

### Разбор:

```
┌─────────────────────────────────────────────────┐
│ Uncaught TypeError                               │ ← Тип ошибки
│ Cannot read properties of null                   │ ← Что случилось
│ (reading 'value')                                │ ← Что пытался сделать
│                                                  │
│ at HTMLButtonElement.addTask                     │ ← Где случилось (функция)
│ at app.js:15:25                                  │ ← Файл:строка:символ
│                                                  │
│ at HTMLFormElement.onsubmit                      │ ← Как попал сюда
│ at index.html:12:35                              │ ← Откуда вызвал
└─────────────────────────────────────────────────┘
```

### Что важно для ИИ:

```
✅ Тип ошибки: TypeError, ReferenceError, SyntaxError
✅ Сообщение: Cannot read properties of null
✅ Файл и строка: app.js:15
✅ Функция: addTask

ИИ использует это для понимания проблемы!
```

## Часть 6: Типичные ошибки новичка

### Ошибка 1: TypeError: Cannot read properties of null

```
Что значит:
Пытаешься обратиться к чему-то, чего не существует.

Пример:
document.getElementById('my-button').value
Но элемента с id="my-button" нет!

Решение:
Проверь, что элемент существует.
Проверь правильность id.
```

### Ошибка 2: ReferenceError: x is not defined

```
Что значит:
Используешь переменную, которая не объявлена.

Пример:
let message = hello;  // hello не в кавычках!
let message = hello;  // hello не объявлена как переменная

Решение:
Проверь опечатки.
Проверь, что переменная объявлена (let, const, var).
```

### Ошибка 3: SyntaxError: Unexpected token

```
Что значит:
Синтаксическая ошибка (опечатка в коде).

Пример:
function addTask( {  // пропущена закрывающая скобка )
function addTask() {  // правильно

Решение:
Проверь все скобки, кавычки, запятые.
```

## Часть 7: Как ИИ помогает понять ошибку?

### Промпт:

```
"Объясни эту ошибку простыми словами:

[вставь ошибку]

Я не программист. Скажи:
1. Что случилось?
2. Где проблема?
3. Как это исправить?"
```

### Пример ответа ИИ:

```
🔧 Что случилось:
Ты пытаешься прочитать 'value' у элемента, 
которого не существует.

📍 Где проблема:
В файле app.js на строке 15 
код ищет элемент, но не находит его.

💡 Как исправить:
Проверь, что в HTML есть элемент 
с правильным id.

Проблема скорее всего здесь:
document.getElementById('task-input').value
                              ↑
                     Проверь этот id в HTML

В HTML должно быть:
<input id="task-input" ...>
     ↑ должен совпадать
```

## Часть 8: Советы по копированию ошибок

### Как скопировать ошибку из браузера:

```
1. F12 → Console
2. Наведи на красное сообщение
3. Правый клик → Copy message
4. Или выдели текст и Ctrl+C
```

### Как скопировать из терминала:

```
1. Выдели текст ошибки мышью
2. Ctrl+Shift+C (Linux) или Cmd+C (Mac)
3. Или используй middle-click для paste
```

### Важно:

```
✅ Копируй ВЕСЬ текст ошибки
✅ Копируй stack trace (все строки)
✅ Копируй файлы, на которые указывает ошибка

❌ Не обрезай ошибку
❌ Не переписывай вручную (опечатки!)
❌ Не игнорируй часть сообщения
```

## 🧠 Ключевые принципы

| Принцип | Объяснение |
|---------|------------|
| **F12 — твой друг** | Консоль браузера показывает все ошибки |
| **Полный лог** | Копируй всю ошибку, не обрезай |
| **Шаблон бага** | Используй структурированное описание |
| **Проси объяснить** | ИИ может объяснить ошибку простыми словами |
| **Файл:строка** | Ошибка всегда указывает где проблема |
