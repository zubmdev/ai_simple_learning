# День 4: Мини-эвал и тесты — вход → ожидаемый выход ✅

**Трек:** 🌱 Начинающий | **Время:** 50 минут

---

## 🎯 Цель дня

Собрать мини-эвал — список входов с ожидаемыми выходами, который прогоняется после каждого изменения агента, — и автоматизировать его первые проверки тестами.

---

## Часть 1: Что такое эвал и тест?

**Эвал** (от evaluation, проверка) — это твой чек-лист: набор входов и ожидаемых выходов, который ты прогоняешь руками после каждого изменения.

**Тест** — та же проверка, только её выполняет программа, а не ты.

Аналогия: завод лампочек. Каждая лампочка проходит проверки: включается? светит? не перегревается? Прошла все — годна. Провалила одну — брак. Без этих проверок завод узнает о браке от покупателя.

```text
Твой проект — тот же завод:
Вход 1: «Купить молоко» → нажать «Добавить» → задача в списке
Вход 2: «» (пусто)      → нажать «Добавить» → ничего не добавилось
Вход 3: перезагрузка    → задачи на месте
```

---

## Часть 2: Мини-эвал для новичка 📝

### Шаг 1: Создай EVALS.md

```markdown
# Эвал To-Do App
Прогонять после КАЖДОГО изменения агента.

| # | Вход | Действие | Ожидаемый выход | OK? |
|---|------|----------|-----------------|-----|
| 1 | «Купить молоко» | нажать «Добавить» | задача появилась в списке | ⬜ |
| 2 | пустая строка | нажать «Добавить» | задача НЕ добавилась | ⬜ |
| 3 | текст 250 символов | нажать «Добавить» | сообщение об ошибке длины | ⬜ |
| 4 | две задачи | перезагрузить страницу | обе задачи на месте | ⬜ |
| 5 | задача есть | нажать «Удалить» | задача исчезла | ⬜ |
```

### Шаг 2: Правило недели

```text
Агент внёс изменение → прогони эвал (хотя бы строки 1–2).
Зелёный эвал → следующая задача.
Красная строка → вернись в дебаг-цикл: воспроизведи, контекст, один фикс.
```

💡 Без эвала ты узнаёшь о поломке через три задачи, когда непонятно, какое изменение её вызвало. С эвалом — сразу после виновника.

### Шаг 3: Пополняй эвал вместе с агентом

Каждая новая функция — новая строка в таблице:

```text
Я добавляю функцию [название]. Предложи 2–3 строки для моего
эвала в EVALS.md: вход, действие, ожидаемый выход.
Включи один «неправильный» вход (пусто, слишком длинно, не то).
```

## Часть 3: Автоматические тесты через агента 🤖

Строки эвала, которые проверяют логику, можно превратить в тесты — их прогоняет одна команда.

### Шаг 1: Установи тестовый запуск (один раз)

В папке проекта:

```bash
npm init -y
npm install --save-dev jest
```

### Шаг 2: Попроси агента написать тесты

Прикрепи `app.js` и `EVALS.md`:

```text
Файлы: app.js, EVALS.md

Напиши тесты на Jest для строк 1, 2 и 5 из EVALS.md:
- addTask с обычным текстом добавляет задачу
- addTask с пустой строкой НЕ добавляет задачу
- deleteTask удаляет задачу

Положи их в app.test.js. Объясни каждую проверку одним предложением.
```

### Шаг 3: Запусти

```bash
npm test
```

Ожидаемый результат:

```text
PASS  ./app.test.js
  addTask
    ✓ добавляет задачу с обычным текстом
    ✓ не добавляет задачу с пустой строкой
  deleteTask
    ✓ удаляет задачу

Tests: 3 passed, 3 total
```

Если тест упал — это подарок: полный вывод ошибки отдай агенту как контекст (День 2), одобри дифф с одним изменением (День 3), запусти `npm test` снова.

## Часть 4: Эвал vs тесты — что когда?

```text
Руками (эвал):
- внешний вид, кнопки, мобильная ширина
- то, что проверяется «глазами»

Тестами (Jest):
- логика: добавление, удаление, сохранение
- то, что прогоняется после каждого изменения за 2 секунды
```

Не стремись автоматизировать всё. Пять тестов на логику + ручной прогон внешнего вида покрывают проект новичка с запасом.

---

## 🧠 Ключевые принципы

| Принцип | Объяснение |
|---------|------------|
| **Эвал — это дифф-щит** | Изменение без прогона эвала не считается готовым |
| **Вход → ожидаемый выход** | Каждая строка проверяема, без «вроде работает» |
| **Краевые случаи** | Пусто, слишком длинно, не то — минимум 3 строки |
| **Тесты через агента** | Не нужно знать Jest — нужно знать, ЧТО проверять |
| **Упал тест → контекст** | Полный вывод ошибки агенту, один фикс, перезапуск |
