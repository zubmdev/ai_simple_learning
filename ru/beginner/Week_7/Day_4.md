## Часть 1: Что такое тесты?

### Определение:

**Тест** — это проверка, что код работает правильно.

### Аналогия:

```
Тесты = Проверка качества на заводе

Представь завод, который делает лампочки:
- Тест 1: Лампочка включается? ✅
- Тест 2: Лампочка светит ярко? ✅
- Тест 3: Лампочка не греется слишком сильно? ✅

Если все тесты пройдены → Лампочка годная!
Если тест провален → Лампочка брак.
```

### В программировании:

```
Тест 1: Кнопка "Добавить" работает? ✅
Тест 2: Задача появляется в списке? ✅
Тест 3: Задача сохраняется в localStorage? ✅

Если все тесты пройдены → Код работает!
Если тест провален → Что-то сломалось.
```

## Часть 2: Зачем нужны тесты?

### Без тестов:

```
1. Изменил код
2. Запустил приложение
3. Прошёлся по всем функциям вручную
4. Нашёл баг
5. Исправил
6. Повторил п.2-5

⏰ Долго и нудно!
```

### С тестами:

```
1. Изменил код
2. Запустил тесты: npm test
3. Тесты сказали: ✅ Всё работает!
   или: ❌ Вот что сломалось

⏰ Быстро и автоматически!
```

## Часть 3: Типы тестов

### Unit тесты (модульные):

```
Проверяют одну маленькую функцию.

Пример:
"Проверь, что функция addTask()
добавляет задачу в массив"

Размер: Маленький
Скорость: Быстрый
```

### Integration тесты (интеграционные):

```
Проверяют, как части работают вместе.

Пример:
"Проверь, что при нажатии кнопки
задача появляется в HTML"

Размер: Средний
Скорость: Средний
```

### E2E тесты (End-to-End):

```
Проверяют весь процесс от начала до конца.

Пример:
"Открой браузер, введи задачу,
нажми 'Добавить', проверь, что 
задача в списке"

Размер: Большой
Скорость: Медленный
```

## Часть 4: Как писать тесты через промпты?

### Промпт 1: Базовый тест

```
@Files: app.js

Напиши тест для функции addTask.

Проверь:
1. Функция добавляет задачу в массив
2. У задачи есть правильный текст
3. У задачи есть уникальный id

Используй Jest (тестовый фреймворк).
```

### Результат ИИ:

```javascript
// app.test.js
import { addTask, tasks } from './app.js';

describe('addTask', () => {
    beforeEach(() => {
        // Очищаем задачи перед каждым тестом
        tasks.length = 0;
    });

    test('должна добавлять задачу в массив', () => {
        addTask('Купить молоко');
        
        expect(tasks.length).toBe(1);
    });

    test('должна сохранять правильный текст задачи', () => {
        addTask('Купить молоко');
        
        expect(tasks[0].text).toBe('Купить молоко');
    });

    test('должна генерировать уникальный id', () => {
        addTask('Задача 1');
        addTask('Задача 2');
        
        expect(tasks[0].id).not.toBe(tasks[1].id);
    });
});
```

### Промпт 2: Тест для UI

```
@Files: index.html, app.js

Напиши тест для пользовательского интерфейса:
1. Открой страницу в браузере
2. Введи текст в поле
3. Нажми кнопку "Добавить"
4. Проверь, что задача появилась в списке

Используй Playwright или Cypress.
```

### Результат ИИ:

```javascript
// e2e.test.js
import { test, expect } from '@playwright/test';

test('должна добавлять задачу в список', async ({ page }) => {
    // Открываем страницу
    await page.goto('http://localhost:3000');
    
    // Вводим текст
    await page.fill('#task-input', 'Купить молоко');
    
    // Нажимаем кнопку
    await page.click('button[type="submit"]');
    
    // Проверяем, что задача в списке
    const taskText = await page.textContent('.task-text');
    expect(taskText).toBe('Купить молоко');
    
    // Проверяем, что поле очищено
    const inputValue = await page.inputValue('#task-input');
    expect(inputValue).toBe('');
});
```

### Промпт 3: Тест на ошибку

```
@Files: app.js

Напиши тест для проверки ошибок:
1. Что если передать пустую строку?
2. Что если передать очень длинную строку?
3. Что если передать число вместо строки?

Функция должна обработать эти случаи.
```

### Результат ИИ:

```javascript
describe('addTask error handling', () => {
    test('не должна добавлять пустую задачу', () => {
        const result = addTask('');
        
        expect(result).toBe(false);
        expect(tasks.length).toBe(0);
    });

    test('не должна добавлять задачу длиннее 200 символов', () => {
        const longText = 'a'.repeat(201);
        const result = addTask(longText);
        
        expect(result).toBe(false);
        expect(tasks.length).toBe(0);
    });

    test('не должна принимать число вместо строки', () => {
        const result = addTask(123);
        
        expect(result).toBe(false);
        expect(tasks.length).toBe(0);
    });
});
```

## Часть 6: Как описать тест простыми словами?

### Шаблон:

```markdown
## Что тестируем
[Функция или компонент]

## Что должно происходить
1. [Шаг 1]
2. [Шаг 2]
3. [Ожидаемый результат]

## Краевые случаи (edge cases)
- [Что если пустой ввод?]
- [Что если неверные данные?]
- [Что если ошибка?]
```

### Пример промпта:

```
Напиши тесты для кнопки "Удалить задачу".

## Что тестируем
Кнопка удаления задачи из списка

## Что должно происходить
1. Задача есть в списке
2. Нажимаю кнопку "Удалить"
3. Задача исчезает из списка
4. Задача удаляется из localStorage

## Краевые случаи
- Что если удалять несуществующую задачу?
- Что если удалить последнюю задачу?
- Что если пользователь передумал (confirm)?

Используй Jest для логики и Playwright для UI.
```

## Часть 8: Почему тесты = документация?

### Тесты показывают:

```
1. Как использовать функцию (примеры)
2. Что функция должна делать (ожидания)
3. Что считается ошибкой (edge cases)
4. Какой API у функции (параметры)

Тесты = Живая документация!
```

### Пример:

```javascript
// Тест показывает, как использовать addTask
test('пример использования addTask', () => {
    const result = addTask('Купить молоко');
    
    // Результат - задача с id и текстом
    expect(result).toEqual({
        id: expect.any(Number),
        text: 'Купить молоко',
        completed: false
    });
});
```

## 🧠 Ключевые принципы

| Принцип | Объяснение |
|---------|------------|
| **Тест = Проверка** | Автоматическая проверка, что работает |
| **Unit → Integration → E2E** | От простого к сложному |
| **Пиши через промпты** | Не нужно знать Jest, Playwright |
| **Тесты = Документация** | Показывают, как использовать код |
| **Запускай часто** | После каждого изменения |
