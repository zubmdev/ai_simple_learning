# День 1: Искусство отладки — Почему ИИ ходит по кругу 🔄

**Трек:** 🌱 Начинающий | **Время:** 35 минут

---

## 🎯 Цель дня

Понять, почему ИИ иногда повторяет одни и те же ошибки, и научиться разрывать этот цикл.

---

## Часть 1: Проблема циклических ошибок

### Что такое "циклическая ошибка"?

```
Ты: "Исправь баг A"
ИИ: Исправляет, но создаёт баг B
Ты: "Исправь баг B"
ИИ: Исправляет, но возвращает баг A
Ты: "Исправь баг A"...
(И так по кругу ♻️)
```

### Пример из жизни:

```
Ты: "Добавь кнопку 'Сохранить' на страницу"

ИИ: Добавляет кнопку, но забыл подключить JavaScript

Ты: "Кнопка не работает"

ИИ: Добавляет JavaScript, но ломает HTML структуру

Ты: "Страница выглядит криво"

ИИ: Исправляет HTML, но удаляет JavaScript

Ты: "Кнопка снова не работает!"
(ИИ вернулся к началу цикла ♻️)
```

---

## Часть 2: Почему это происходит?

### Причина 1: Недостаток контекста

```
ИИ видит только то, что ты дал в текущем промпте.

Если ты говоришь:
"Исправь это"
ИИ не помнит, что было 5 промптов назад.

Он "забыл" про предыдущие изменения!
```

### Причина 2: Противоречивые требования

```
Ты говоришь:
"Сделай кнопку красной"

Потом:
"Сделай, чтобы кнопка подходила к синему дизайну"

ИИ пытается удовлетворить оба требования:
- Красная кнопка
- Подходит к синему дизайну

Результат: путаница и ошибки
```

### Причина 3: Слишком много изменений сразу

```
❌ Плохо:
"Добавь кнопку, подключи её, стилизуй, 
сделай анимацию, добавь звук, 
сохрани в localStorage"

ИИ пытается сделать всё сразу → ошибки

✅ Хорошо:
"Добавь кнопку" (одно изменение)
(проверяем)
"Подключи её" (одно изменение)
(проверяем)
...
```

## Часть 3: Как разорвать цикл?

### Техника 1: "Сделай шаг назад" 🚶

```
Промпт:
"Стоп. Забудь предыдущие изменения.
Давай начнём сначала.

Вот текущее состояние файла:
[вставь текущий код]

Вот что нужно сделать:
[опиши цель]

Не ломай существующий функционал."
```

### Пример:

```
Ты: 
"Стоп. Проблема: кнопка не работает.

Текущий код:
[вставь index.html]

Цель: 
- Кнопка должна быть видимой
- При нажатии показывать alert
- Не менять ничего другого

Начни сначала, не учитывая предыдущие попытки."
```

---

### Техника 2: "Проверь перед исправлением" ✅

```
Промпт:
"Прежде чем исправлять, ответь:
1. Какой текущий код?
2. В чём именно проблема?
3. Что нужно изменить?
4. Что может сломаться?

Потом предложи исправление."
```

### Пример:

```
Ты:
"Прежде чем исправлять кнопку, скажи:
1. Покажи текущий HTML кнопки
2. Покажи текущий JavaScript
3. Почему не работает?
4. Что именно нужно исправить?
5. Что ещё может сломаться?"

ИИ анализирует, а не сразу правит код.
```

---

### Техника 3: "Один файл за раз" 📄

```
❌ Плохо:
"Исправь баги во всех файлах"

✅ Хорошо:
"Давай исправим по порядку:
1. Сначала index.html
(проверяем)
2. Потом styles.css
(проверяем)
3. Потом app.js
(проверяем)
"
```

---

### Техника 4: "Якорь" ⚓

```
Создай "якорь" — файл с правильным состоянием.

Промпт:
"Создай файл WORKING_STATE.md с описанием:
- Что работает сейчас
- Как должно работать
- Что НЕ трогать

Перед каждым исправлением проверяй этот файл."
```

### Пример WORKING_STATE.md:

```markdown
# Working State

## Что работает ✅
- Страница загружается
- Форма отображается
- Стили применяются

## Цель 🎯
- Добавить работающую кнопку

## НЕ трогать 🚫
- index.html (кроме добавления кнопки)
- styles.css (кроме стилей кнопки)
- Любой существующий код
```

## Часть 4: Практика — Разрыв цикла

### Сценарий: "Сломанная" кнопка

Представь ситуацию:

```
Ты попросил добавить кнопку "Очистить".
ИИ добавил, но теперь:
1. Кнопка не видна
2. Или видна, но не работает
3. Или работает, но сломалась другая кнопка
```

### Решение через техники:

```
Применяем Технику 1 + 2:

"Стоп. Давай начнём сначала.

Текущее состояние файлов:
@Files: index.html, app.js

Прежде чем исправлять, ответь:
1. Где должна быть кнопка "Очистить"?
2. Какой у неё сейчас код?
3. Почему не работает?
4. Что нужно изменить?

Потом предложи решение.

Цель: Добавить кнопку, которая очищает список задач.
НЕ ломать: существующую кнопку 'Добавить' и список задач."
```

## Часть 5: Чеклист перед каждым исправлением

### Задай себе вопросы:

```
□ Что именно не работает?
□ Какой файл содержит проблему?
□ Что я менял в последний раз?
□ Что НЕ должно сломаться?
□ Как проверить, что всё работает?
```

### Промпт для ИИ:

```
"Проблема: [опиши конкретно]

Текущий код:
[вставь файл]

Что было до: [опиши]
Что изменилось: [опиши]

Цель: [что должно работать]
НЕ трогать: [что не менять]

Предложи решение, объясни каждый шаг."
```

## Часть 6: Красные флаги 🚩

### Если видишь это — остановись:

```
🚩 ИИ предложил то же решение 3-й раз
→ Используй технику "Сделай шаг назад"

🚩 Исправление ломает то, что работало
→ Используй технику "Якорь"

🚩 ИИ не понимает, что не так
→ Дай больше контекста (весь файл, логи)

🚩 Слишком много изменений сразу
→ Разбей на маленькие шаги
```

---

## 🧠 Ключевые принципы

| Принцип | Объяснение |
|---------|------------|
| **Сделай шаг назад** | Начни сначала с чистого листа |
| **Проверь перед исправлением** | Пусть ИИ анализирует, а не сразу правит |
| **Один файл за раз** | Не меняй всё одновременно |
| **Якорь** | Зафиксируй рабочее состояние |
| **Маленькие шаги** | Одно изменение = один промпт |
