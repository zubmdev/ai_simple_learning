# День 1: Дебаг-цикл — воспроизведи, дай контекст, проверь 🔄

**Трек:** 🌱 Начинающий | **Время:** 35 минут

---

## 🎯 Цель дня

Освоить дебаг-цикл из четырёх шагов: когда изменение агента что-то сломало — воспроизвести баг, дать ошибку как контекст, внести одно изменение и проверить результат.

---

## Часть 1: Почему агент «ходит по кругу» ♻️

Знакомая ситуация:

```text
Ты: «Кнопка не работает, исправь»
Агент: правит JavaScript, но ломает вёрстку
Ты: «Теперь страница кривая»
Агент: правит вёрстку, но удаляет JavaScript
Ты: «Кнопка снова не работает!»
(цикл замкнулся)
```

Три причины цикла:

```text
1. Мало контекста — агент видит только текущий промпт,
   а не то, что он менял три задачи назад.
2. Противоречивые требования — «сделай красной» и
   «она должна подходить к синему дизайну» одновременно.
3. Слишком много изменений сразу — кнопка + звук + анимация
   в одном запросе. Сломалось — непонятно, что именно.
```

## Часть 2: Дебаг-цикл — 4 шага 🩺

Аналогия: хороший врач сначала воспроизводит симптом (просит описать боль), смотрит анализы (логи), лечит одну болезнь за раз и после назначенного лечения спрашивает «стало ли лучше?». Никто не выписывает пять таблеток наугад.

```text
Шаг 1. ВОСПРОИЗВЕДИ
       Сделай так, чтобы баг случился прямо сейчас.
       Запиши шаги: что нажал, что ожидал, что вышло.

Шаг 2. ДАЙ КОНТЕКСТ
       Полный текст ошибки + файлы, к которым она относится.

Шаг 3. ОДНО ИЗМЕНЕНИЕ
       Один конкретный фикс за раз. Не «перепиши всё».

Шаг 4. ПРОВЕРЬ
       Прогони шаги воспроизведения снова.
       Баг ушёл? Всё остальное живо? Только потом следующий шаг.
```

💡 Круг разрывается на шаге 1: пока баг не воспроизводится по шагам, агент лечит симптомы, а не причину. Шаги воспроизведения — это и есть главный контекст.

---

## Часть 3: Практика в Cline 🛠️

### Шаг 1: Воспроизведи и опиши

Открой свой проект (например, To-Do App из недели 6), вызови баг и дай агенту полный контекст:

```text
Стоп. Сначала воспроизведение, без правок кода.

Симптом: [что именно не работает]
Шаги воспроизведения:
1. [открываю страницу]
2. [ввожу текст, нажимаю «Добавить»]
3. [ничего не происходит]

Ошибка из консоли (F12 → Console):
[вставь ПОЛНЫЙ текст ошибки]

Файлы: [прикрепи index.html и app.js]

Сначала объясни, в чём причина. Код пока не меняй.
```

### Шаг 2: Одно изменение за раз

Когда причина понятна:

```text
Причина понятна. Внеси ОДНО изменение: [конкретный фикс].

Не трогай ничего другого. Покажи diff перед применением —
я хочу прочитать, что именно ты меняешь.
```

### Шаг 3: Проверь до Approve

Прочитай diff (красные строки — удалено, зелёные — добавлено). Изменён только то, о чём ты просил? Одобряй. После применения — прогони шаги воспроизведения: баг ушёл, остальное работает.

Если агент предложил то же самое третий раз — не спорь: откати задачу в Cline (Restore checkpoint) и начни новый диалог с полным контекстом, как в шаге 1.

---

## Часть 4: Как понять, что цикл разорван

```text
✅ Баг воспроизводится по записанным шагам (до и после фикса)
✅ Агент ответил «в чём причина» ДО правки кода
✅ Diff содержал одно изменение, и ты его прочитал
✅ Шаги воспроизведения больше не ломают приложение
✅ Всё остальное тоже работает
```

---

## 🧠 Ключевые принципы

| Принцип | Объяснение |
|---------|------------|
| **Воспроизведи** | Баг без шагов воспроизведения не чинят — угадывают |
| **Контекст** | Полная ошибка + файлы, а не «не работает» |
| **Одно изменение** | Один фикс за раз — понятно, что помогло |
| **Проверь** | Прогони шаги воспроизведения после каждого изменения |
| **Шаг назад** | Ходит по кругу → откат задачи + новый диалог с контекстом |

## 🎯 Миссия дня

Создай в папке проекта файл `DEBUG_LOG.md` и сделай первую запись по шаблону:

```markdown
# Дебаг-журнал

## Баг #1 — [дата]
- Симптом: [что не работает]
- Шаги воспроизведения: 1) ... 2) ... 3) ...
- Ошибка из консоли: [полный текст]
- Причина (объяснил агент): [...]
- Что изменили: [одно изменение]
- Проверка: шаги 1–3 больше не ломают приложение ✅
```

**Проверка:** файл `DEBUG_LOG.md` лежит в проекте, и баг из записи реально исправлен — шаги воспроизведения проходят чисто.
