# День 3: Diff-ревью перед Approve и откат 🔀

**Трек:** 🌱 Начинающий | **Время:** 45 минут

---

## 🎯 Цель дня

Научиться читать diff перед каждым одобрением и откатывать любые изменения агента к последнему рабочему состоянию.

---

## Часть 1: Что такое diff?

**Diff** — это список изменений: какие строки удалены и какие добавлены.

Аналогия: дифф — это правки юриста в договоре перед подписью. Ты не подписываешь договор не глядя — ты читаешь, что изменилось. Кнопка Approve в Cline — это подпись.

```text
Красные строки (−) — то, что будет УДАЛЕНО
Зелёные строки (+) — то, что будет ДОБАВЛЕНО

Каждое Approve = подпись под этим списком.
```

💡 Агент предлагает дифф, а не истину. Прочитанный diff — разница между «я режиссёр проекта» и «я свидетель того, что случилось».

---

## Часть 2: Что смотреть в диффе перед Approve

Три вопроса к каждому диффу:

```text
1. Масштаб: изменено столько, сколько я просил?
   Просил одну строку — а правок на 40? Отклони.

2. Границы: тронуты ли файлы ВНЕ задачи?
   Просил app.js — а правится styles.css? Отклони.

3. Удаления: что именно удаляется?
   Удалённая проверка валидации или рабочая функция —
   это не «упрощение», а потеря функционала.
```

Красные флаги 🚩:

```text
🚩 Агент «заодно» переименовал переменные по всему файлу
🚩 Удалены комментарии, проверки или обработка ошибок
🚩 Изменений больше, чем слов в твоей задаче
🚩 Появились файлы, о которых ты не просил
```

---

## Часть 3: Страховка — якорь в git ⚓

Перед рискованным изменением зафиксируй рабочее состояние:

```bash
git add .
git commit -m "Рабочее состояние перед изменением X"
```

Теперь у тебя есть точка возврата: куда бы агент ни унёс проект, ты всегда можешь вернуться к этому состоянию. Это и есть «известное хорошее состояние».

Правило простое: **коммит перед каждой новой задачей агенту.** Один коммит = одно известное рабочее состояние.

---

## Часть 4: Откат — три способа

### Способ 1: Откат задачи в Cline

У каждой задачи в Cline есть откат к состоянию до неё (Restore checkpoint). Агент унёс проект не туда — откатывай задачу целиком и формулируй запрос заново, с лучшим контекстом.

### Способ 2: Вернуть один файл из git

```bash
git status              # посмотри, какие файлы изменены
git diff                # посмотри сами изменения
git restore app.js      # верни ОДИН файл к последнему коммиту
```

### Способ 3: Вернуть всё к последнему коммиту

```bash
git restore .
```

🚨 `git restore` стирает несохранённые изменения — это его работа. Всё, что не закоммичено, будет потеряно: сначала сохрани в коммит то, что хочешь оставить, потом откатывай остальное.

---

## Часть 5: Практика — drills 🛠️

### Упражнение 1: Ручной дифф и откат

```bash
# 1. Сделай якорь
git add .
git commit -m "Рабочее состояние"

# 2. Сломай файл руками: открой app.js и удали любую строку
# 3. Посмотри, что изменилось:
git diff
git status

# 4. Откатись:
git restore app.js

# 5. Проверь:
git status   # должно быть чисто
```

Открой страницу — приложение работает как до поломки. Ты только что сделал полный цикл «изменение → дифф → откат».

### Упражнение 2: Дифф агента — одобрить осознанно

```text
Добавь валидацию: задача не добавляется, если поле пустое.
Покажи diff перед применением и объясни каждую правку одним предложением.
```

Прочитай дифф по трём вопросам из Части 2. Только потом Approve. Прогони проверку: пустая задача не добавляется, обычные добавляются.

### Упражнение 3: Дифф агента — отклонить

```text
Улучши весь проект.
```

Посмотри на дифф: десятки строк в нескольких файлах без ясной причины. Отклони и переформулируй:

```text
Слишком много изменений. Одно улучшение за раз:
сначала только имена переменных в app.js. Остальное — потом, после моей проверки.
```

---

## Часть 6: Когда отклонять, а когда откатывать

```text
Отклони (до Approve), если:
- дифф ещё не применён, и он шире задачи

Откатывай (после Approve), если:
- применил, проверил — сломалось
- агент ходит по кругу: 2-3 попытки без результата
```

Откат — не провал, а рутина. Опытный пользователь агентов откатывается чаще новичка: он просто замечает раньше.

---

## 🧠 Ключевые принципы

| Принцип | Объяснение |
|---------|------------|
| **Дифф = договор** | Читай до подписи (Approve), а не после |
| **Три вопроса** | Масштаб, границы, удаления |
| **Якорь** | Коммит перед каждой задачей агенту |
| **Откат — рутина** | `git restore` / Restore checkpoint без чувства вины |
| **Уже круг? Откат** | 2–3 неудачные попытки = возврат и новый запрос |

```text
1. Якорь: git add . && git commit -m "Перед миссии дня 3"

```

**Проверка:** `git status` показывает чистую рабочую папку, в `DEBUG_LOG.md` появилась запись «Баг #2»: что менял агент, почему откатил, чем проверил.
