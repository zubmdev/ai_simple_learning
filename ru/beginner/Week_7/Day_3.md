## Часть 1: Что такое рефакторинг?

### Определение:

**Рефакторинг** — это улучшение кода без изменения его поведения.

### Аналогия:

```
Рефакторинг = Уборка в комнате

Ситуация до:
- Вещи валяются где попало
- Трудно найти нужное
- Пыльно и грязно

Ситуация после:
- Всё по полочкам
- Легко найти
- Чисто и приятно

Но функционал тот же:
Ты всё так же можешь пользоваться вещами!
```

### В коде:

```
До рефакторинга:
- Длинные функции (100 строк)
- Непонятные имена (x, temp, data)
- Повторяющийся код
- Трудно читать

После рефакторинга:
- Короткие функции (10-20 строк)
- Понятные имена (userName, orderTotal)
- Без повторов
- Легко читать

Но функционал тот же:
Всё работает так же, как и раньше!
```

---

## Часть 2: Почему рефакторинг важен?

### Проблема плохого кода:

```
❌ Трудно читать → Медленно понимать
❌ Трудно менять → Страшно править
❌ Много повторов → Ошибки копируются
❌ Непонятные имена → Путаница
```

### Польза хорошего кода:

```
✅ Легко читать → Быстро понимать
✅ Легко менять → Не страшно править
✅ Без повторов → Меньше ошибок
✅ Понятные имена → Ясность
```

## Часть 3: Примеры рефакторинга

### Пример 1: Имена переменных

#### До:

```javascript
let x = document.getElementById('input1').value;
let y = document.getElementById('input2').value;
let z = x + y;
```

#### После:

```javascript
let firstName = document.getElementById('firstName').value;
let lastName = document.getElementById('lastName').value;
let fullName = firstName + ' ' + lastName;
```

**Что изменилось:**
- `x` → `firstName` (понятно, что это)
- `y` → `lastName` (понятно, что это)
- `z` → `fullName` (понятно, что это)
- Функционал тот же, но читать легче!

---

### Пример 2: Разбиение функции

#### До:

```javascript
function processForm() {
    // Получаем данные
    let name = document.getElementById('name').value;
    let email = document.getElementById('email').value;
    let message = document.getElementById('message').value;
    
    // Валидируем
    if (name.length < 2) {
        alert('Имя слишком короткое');
        return;
    }
    if (!email.includes('@')) {
        alert('Email неверный');
        return;
    }
    if (message.length < 10) {
        alert('Сообщение слишком короткое');
        return;
    }
    
    // Отправляем
    fetch('/api/contact', {
        method: 'POST',
        body: JSON.stringify({ name, email, message })
    });
    
    // Показываем успех
    alert('Отправлено!');
}
```

#### После:

```javascript
function processForm() {
    const formData = getFormData();
    
    if (!validateForm(formData)) {
        return;
    }
    
    await submitForm(formData);
    showSuccess();
}

function getFormData() {
    return {
        name: document.getElementById('name').value,
        email: document.getElementById('email').value,
        message: document.getElementById('message').value
    };
}

function validateForm(data) {
    if (data.name.length < 2) {
        showError('Имя слишком короткое');
        return false;
    }
    if (!data.email.includes('@')) {
        showError('Email неверный');
        return false;
    }
    if (data.message.length < 10) {
        showError('Сообщение слишком короткое');
        return false;
    }
    return true;
}

async function submitForm(data) {
    await fetch('/api/contact', {
        method: 'POST',
        body: JSON.stringify(data)
    });
}

function showSuccess() {
    alert('Отправлено!');
}

function showError(message) {
    alert(message);
}
```

**Что изменилось:**
- Одна большая функция → 6 маленьких
- Каждая функция делает одно
- Легче читать и понимать
- Функционал тот же!

## Часть 4: Как просить ИИ сделать рефакторинг?

### Промпт 1: Базовый рефакторинг

```
@Files: app.js

Сделай рефакторинг этого файла:
- Улучши имена переменных
- Разбей длинные функции на маленькие
- Удали дублирующийся код
- Добавь комментарии

ВАЖНО: 
- НЕ меняй функционал
- Всё должно работать так же
- Только улучши читаемость
```

### Промпт 2: Конкретные улучшения

```
@Files: app.js

Улучши функцию addTask:
- Сейчас она слишком длинная
- Разбей на логические части
- Используй понятные имена

Функционал НЕ менять!
```

### Промпт 3: Проверка после рефакторинга

```
@Files: app.js (до), app_refactored.js (после)

Сравни два файла:
1. Функционал одинаковый?
2. Что улучшилось?
3. Что может сломаться?
4. Стоит ли применять эти изменения?
```

## Часть 5: Правила безопасного рефакторинга

### Правило 1: Маленькие шаги

```
❌ Плохо:
"Переделай весь файл целиком"

✅ Хорошо:
"Улучши функцию addTask"
(проверяем)
"Улучши функцию deleteTask"
(проверяем)
```

### Правило 2: Проверяй после каждого шага

```
1. Попроси рефакторинг
2. Примени изменения
3. Запусти приложение
4. Проверь, что работает
5. Если сломалось → откатись
```

### Правило 3: Сохрани рабочую версию

```
Перед рефакторингом:
cp app.js app.js.backup

Или создай git commit:
git add app.js
git commit -m "Before refactoring"
```

### Правило 4: Тесты — твой щит

```
Если есть тесты → рефакторинг безопаснее!

Промпт:
"Напиши тесты для проверки функционала:
- addTask добавляет задачу
- deleteTask удаляет задачу

Потом сделай рефакторинг.
Запусти тесты.
Если тесты прошли → рефакторинг OK."
```

## Часть 6: Что просить при рефакторинге?

### Улучшение имён:

```
"Улучши имена переменных и функций в app.js.
Используй описательные имена.
Функционал не менять."
```

### Удаление повторов:

```
"Найди повторяющийся код в app.js.
Вынеси его в отдельные функции.
Убери дублирование."
```

### Разбиение функций:

```
"Функция processForm слишком длинная.
Разбей её на маленькие функции.
Каждая функция должна делать одно."
```

### Добавление комментариев:

```
"Добавь комментарии к сложным местам в коде.
Объясни, что делает каждая функция.
Не меняй код, только добавь комментарии."
```
