## Часть 1: День 2 — каркас 🛠️

### Шаг 1: Структура

```bash
mkdir -p ~/projects/my-capstone
cd ~/projects/my-capstone
touch index.html styles.css app.js README.md AGENTS.md PLAN.md EVALS.md
```

### Шаг 2: Каркас через агента

```text
Файлы: PLAN.md

Сделай каркас приложения: index.html, styles.css, app.js.
Пока без логики — только структура интерфейса по плану,
подключение CSS и JS, мобильная адаптивность.

Одна задача — один дифф. Ничего сверх плана.
```

Прочитай дифф: три файла, никаких лишних правок? Approve. Открой `index.html` — каркас виден, консоль чистая.

### Шаг 3: Главная функция

```text
Файлы: PLAN.md, index.html, app.js

Реализуй функцию 1 из плана: [название].
Критерий приёмки: [вход → действие → ожидаемый выход].
Обработка ошибок и сохранение в localStorage по плану.
Не трогай ничего вне этой функции.
```

Дифф → Approve → проверка руками по критерию приёмки → запиши 2-3 строки (включая один «неправильный» вход) в `EVALS.md`.

🚨 Конец Дня 2: сделай коммит-якорь, даже если всё работает. Особенно если всё работает.

```bash
git add .
git commit -m "День 2: каркас + главная функция, эвал зелёный"
```

## Часть 2: Управление контекстом 🧠

```text
При длинных диалогах агент забывает решения и путается в файлах.

1. Каждая задача = свежий контекст: план, нужные файлы, критерий
2. Правила проекта живут в AGENTS.md — агент читает их сам
3. Коммит после каждой закрытой задачи
4. Диалог разросся — начни новый: план + файлы + одна задача
```

Промпт для нового диалога:

```text
НОВЫЙ ДИАЛОГ.

Проект: [название]. Файлы: PLAN.md, AGENTS.md, [нужные файлы].
Сделано: [функция 1 — работает, эвал зелёный].
Задача сейчас: функция 2 из плана — [название].
Критерий приёмки: [...].
Предыдущие диалоги не учитывай.
```

## Часть 3: Какая модель и сколько это стоит 💰

### Три уровня доступа

| Уровень | Железо | Модель | Заметка |
|---------|--------|--------|---------|
| 1 | CPU + бесплатный API | Groq `openai/gpt-oss-20b` | Запасные: Gemini AI Studio, OpenRouter (free-модели) |
| 2 | 4GB GPU + Ollama | `qwen3.5:2b` (запасная `qwen3:4b`) | Локально, без лимитов; простые задачи |
| 3 | 16GB GPU + Ollama | `gpt-oss:20b` (запасные `gemma4:12b`, `qwen3:14b`) | Сложная логика; `qwen3-coder:30b` — только с CPU offload |

**Проверено: 2026-10-24** (модели и лимиты — по ADR-0003; перепроверяй ежеквартально).

### Лимиты бесплатного Тира 1

```text
Groq: ~30 запросов/мин, ~1000/день, 8K токенов/мин, 200K токенов/день
OpenRouter (free-модели): 20 запросов/мин; 50/день, пока на счету
меньше $10, потом до 1000/день. В privacy-настройках отключи
обучение на своих данных.
Ollama: лимитов нет — платишь временем и железом.
```

### Стратегия на неделю

```text
Планирование и код → Groq openai/gpt-oss-20b (быстро, качественно)
Упёрся в дневной лимит → локальная модель или продолжи завтра
Каждый запрос = одна маленькая задача → лимитов хватает с запасом
```

💡 Каждый прикреплённый файл и каждая строка диалога — это токены. Прикрепляй нужные файлы, а не весь проект, — и бесплатного тарифа хватает на весь капстоун. Подробнее о стоимости — в День 4.

## Часть 4: День 3 — остальные функции и полировка ✨

### Каждая функция — по циклу

```text
Промпт (одна функция):
Файлы: PLAN.md, app.js
Реализуй функцию [N]: [название]. Критерий приёмки: [...].
Не ломай то, что уже работает.

Дальше без исключений:
1. Прочитал дифф → Approved
2. Проверил руками по критерию
3. Прогнал эвал (хотя бы строки главной функции)
4. Коммит
```

### Полировка — тоже маленькими задачами

```text
Улучши стили: hover-эффекты на кнопках и адаптив под телефон.
Только CSS, JS не трогай.
```

### Типичные проблемы

```text
Агент предлагает сложное:
→ «Это слишком сложно. Самое простое решение, минимум кода.»

После изменения сломалось старое:
→ git restore . → новый диалог → тот же запрос + «не трогай [функцию]»

Не успеваешь:
→ Оставь 1-2 функции MUST HAVE. Закончить важнее, чем успеть всё.
```

## 🧠 Ключевые принципы

| Принцип | Объяснение |
|---------|------------|
| **Одна задача = один дифф** | Читай перед каждым Approve |
| **Эвал после каждого изменения** | Красная строка = стоп и дебаг-цикл |
| **Свежий контекст** | Каждая задача начинается с плана и файлов |
| **Коммит после задачи** | Всегда есть точка возврата |
| **Маленькие запросы** | Меньше токенов, меньше лимитных проблем |
