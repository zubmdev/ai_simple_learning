# День 1: Идея финального проекта и ограничение Scope 💡

**Трек:** 🌱 Начинающий | **Время:** 40 минут

---

## 🎯 Цель дня

Выбрать идею финального проекта и ограничить масштаб так, чтобы к Дню 4 у тебя было что публиковать.

---

## Часть 1: Выбор идеи

Критерии выбора:

```text
✅ Интересно ТЕБЕ
✅ Реалистично за 2-3 дня работы по 60 минут
✅ Полезно в жизни
✅ Можно показать друзьям по ссылке
✅ Сложность: не выше ⭐⭐
```

### Идеи для новичка:

#### 1. Персональный трекер привычек 📊

```text
Функции: добавить привычку, отметить выполненную,
счётчик за сегодня, сохранение в браузере
Сложность: ⭐⭐
```

#### 2. Генератор списков покупок 🛒

```text
Функции: добавить продукт, категория,
отметить купленным, сохранение списка
Сложность: ⭐
```

#### 3. Таймер для работы (Pomodoro) ⏰

```text
Функции: 25 минут работы, 5 минут перерыв,
старт/стоп/пауза, звуковой сигнал
Сложность: ⭐⭐
```

#### 4. Конвертер валют 💱

```text
Функции: выбор валют, ввод суммы,
показ результата, история конвертаций
Сложность: ⭐⭐
```

## Часть 2: Ограничение Scope (масштаба)

### Правило MVP:

```text
MVP = Minimum Viable Product
Минимально жизнеспособный продукт.

Фокус: ОДНА главная функция, которая работает идеально,
плюс 2-4 вспомогательных. Не больше.
```

### Пример: трекер привычек

❌ Scope creep — нереально за неделю:

```text
Календарь на месяц, графики, уведомления, шаринг,
тёмная тема, экспорт в PDF, синхронизация устройств...
```

✅ Правильный MVP — реалистично за 2-3 дня:

```text
1. Добавлять привычки (текст + иконка)
2. Отмечать выполненной (чекбокс)
3. Счётчик выполненных за сегодня
4. Сохранение в localStorage
```

### Метод отсечения:

```text
1. Выпиши ВСЕ идеи функций (10-20)
2. Отметь обязательные (3-5)
3. Остальное — в v2.0

🔴 MUST HAVE — без этого проект не имеет смысла
🟡 NICE TO HAVE — если останется время
🟢 FUTURE — следующая версия
```

## Часть 3: План проекта 🛠️

Создай `PROJECT_PLAN.md` в папке будущего проекта:

```markdown
# Проект: [Название]

## Цель
[Одно предложение: что делает приложение]

## Функции MVP (3-5, каждая с критерием приёмки)
1. [Функция] — приёмка: [вход → действие → ожидаемый выход]
2. [Функция] — приёмка: [...]
3. [Функция] — приёмка: [...]

## НЕ делаем (v2.0)
- [идея 1]
- [идея 2]

## Технологии
- HTML/CSS/JavaScript, хранение в localStorage

## Структура
project/
├── index.html
├── styles.css
├── app.js
├── AGENTS.md      ← правила агента из недели 6
├── PLAN.md        ← этот план
├── EVALS.md       ← эвал: заполню в День 2
└── README.md

## План недели
- День 1: план (сегодня)
- День 2-3: разработка через агента
- День 4: деплой и учёт стоимости
- День 5: портфолио
```

💡 Критерий приёмки у каждой функции — это строка твоего будущего эвала. Ты пишешь тесты проекта до первой строки кода.

### Промпт для агента:

```text
Я хочу создать [название проекта].

Помоги мне определить MVP:
1. Какие 3-5 функций ОБЯЗАТЕЛЬНЫ?
2. Что отложить в v2.0?
3. Предложи критерий приёмки для каждой функции:
   вход → действие → ожидаемый выход.

Правило: самое простое решение, которое работает.
```

## Часть 4: Проверка реалистичности

```text
□ Главную функцию можно описать одним предложением?
□ Функций MVP — 5 или меньше?
□ Каждая функция имеет критерий приёмки?
□ Нет внешних баз данных и сложных API?
□ Я готов показывать это друзьям через 4 дня?
```

Все «да» → проект реалистичен. Лучше ПРОСТОЙ и ЗАКОНЧЕННЫЙ, чем СЛОЖНЫЙ и брошенный: закончить важнее, чем идеально.

---

## 🧠 Ключевые принципы

| Принцип | Объяснение |
|---------|------------|
| **MVP** | 3-5 функций, не больше |
| **Отсечение** | MUST HAVE отдельно, остальное — v2.0 |
| **Приёмка до кода** | Критерий каждой функции известен заранее |
| **Агент — исполнитель** | План пишешь ты, агент реализует по шагам |
| **Закончи** | Рабочее простое лучше незаконченного сложного |

## 🎯 Миссия дня

Артефакт дня — план, по которому можно строить:

```text
1. Выбери идею и запиши PROJECT_PLAN.md в папку проекта
2. 3-5 функций, у каждой строка «приёмка: вход → действие → выход»
3. Секция «НЕ делаем» с минимум 2 отложенными идеями
4. Скопируй AGENTS.md из проекта недели 6 (правила агента)
```

**Проверка:** открой `PROJECT_PLAN.md` — функций не больше пяти, у каждой есть проверяемый критерий приёмки, `AGENTS.md` лежит рядом.
