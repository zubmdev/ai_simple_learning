## Часть 2: Ограничение Scope (масштаба)

### Правило MVP:

```
MVP = Minimum Viable Product
Минимально жизнеспособный продукт

Фокус: ОДНА главная функция, которая работает идеально
```

### Пример: Трекер привычек

#### ❌ Слишком много (Scope creep):

```
- Добавлять привычки
- Редактировать
- Удалять
- Календарь на месяц
- Графики
- Уведомления
- Шаринг с друзьями
- Темная тема
- Экспорт в PDF
- Синхронизация между устройствами

Нереально за неделю! 📅
```

#### ✅ Правильный MVP:

```
- Добавлять привычки (текст + иконка)
- Отмечать выполненной (чекбокс)
- Счётчик выполненных за сегодня
- Сохранение в localStorage

Реалистично за 2-3 дня! ✅
```

## Часть 3: Метод отсечения

### Техника:

```
1. Напиши ВСЕ идеи (10-20 функций)
2. Отметь "обязательно" (2-3 функции)
3. Остальное — "можно потом"

Функции делятся на:
🔴 MUST HAVE - без этого не работает
🟡 NICE TO HAVE - хорошо бы, но не обязательно
🟢 FUTURE - в следующей версии
```

### Пример для таймера Pomodoro:

```
🔴 MUST HAVE:
- Таймер на 25 минут
- Таймер на 5 минут
- Старт/стоп/пауза
- Звуковой сигнал

🟡 NICE TO HAVE:
- Счётчик помидорок
- Название задачи
- История сессий

🟢 FUTURE:
- Статистика за неделю
- Тёмная тема
- Мобильное приложение
```

## Часть 4: Создание плана проекта

### Шаблон плана:

```markdown
# Проект: [Название]

## Цель
[Одно предложение: что делает приложение]

## Основная функция
[ОПИСАНИЕ ГЛАВНОЙ ФУНКЦИИ]

## Функции MVP (3-5 функций)
1. [Функция 1]
2. [Функция 2]
3. [Функция 3]

## НЕ делаем (отложили)
- [Идея 1]
- [Идея 2]

## Технологии
- Frontend: HTML/CSS/JavaScript
- Хранение: localStorage
- Стили: Свои (или Bootstrap)

## Структура файлов
```
project/
├── index.html
├── styles.css
├── app.js
└── README.md
```

## Время
- День 1: Планирование
- День 2-3: Разработка
- День 4: Тестирование
- День 5: Деплой и документация
```

## Часть 5: Практика — Выбери свой проект

```

```

```
2. Что можно отложить?
3. Реалистично ли это за 3 дня?

Цель: Создать работающее приложение.
```

## Часть 6: Оценка сложности

### Простые проекты (⭐):

```
✅ Мало файлов (3-5)
✅ Простой интерфейс
✅ Нет API запросов
✅ Данные в localStorage

Примеры:
- Список покупок
- Калькулятор
- Заметки
```

### Средние проекты (⭐⭐):

```
✅ Больше файлов (5-10)
✅ Интерактивный интерфейс
✅ Может быть API (опционально)
✅ Данные в localStorage

Примеры:
- Трекер привычек
- Pomodoro таймер
- Конвертер валют
```

### Сложные проекты (⭐⭐⭐):

```
⚠️ Много файлов (10+)
⚠️ Сложный интерфейс
⚠️ API запросы
⚠️ База данных

НЕ РЕКОМЕНДУЕТСЯ для первого проекта!
```

## Часть 7: Проверка реалистичности

### Вопросы к себе:

```
□ Могу ли я описать главную функцию одним предложением?
□ Есть ли у меня 2-3 часа в день на разработку?
□ Понятны ли мне технологии (HTML/CSS/JS)?
□ Могу ли я показать это друзьям через неделю?
□ Есть ли у меня мотивация закончить?
```

### Если на все вопросы "да" → ✅ Проект реалистичен!

---

## Часть 8: Мотивация

### Почему важно закончить?

```
1. Портфолио: Ты сможешь показать проект
2. Навык: Ты научишься доводить до конца
3. Уверенность: "Я могу создать что угодно!"
4. Основа: Этот проект можно расширять
```

### Совет:

```
Лучше ПРОСТОЙ, но РАБОЧИЙ проект,
чем СЛОЖНЫЙ, но НЕЗАКОНЧЕННЫЙ.

Закончить = важнее, чем идеально.
```

## 🧠 Ключевые принципы

| Принцип | Объяснение |
|---------|------------|
| **MVP** | Минимальный жизнеспособный продукт |
| **Scope ограничение** | 3-5 функций, не больше |
| **Метод отсечения** | MUST HAVE vs NICE TO HAVE |
| **Реалистичность** | Закончить важнее, чем идеально |
| **План проекта** | Запиши всё перед началом |
