# День 4: Деплой проекта и стоимость работы агента 💰🚀

**Трек:** 🌱 Начинающий | **Время:** 45 минут

---

## 🎯 Цель дня

Опубликовать финальный проект по простой схеме и посчитать, сколько стоила работа агента в запросах и токенах.

---

## Часть 1: Деплой — проект по ссылке 🛠️

**Деплой** — размещение приложения так, чтобы им можно было пользоваться по ссылке. Для твоего проекта (HTML/CSS/JS) хватает GitHub Pages: бесплатно, без серверов.

Аналогия: до деплоя приложение живёт у тебя дома (твой браузер). После — у него есть публичный адрес, как у квартиры.

### Шаг 1: Репозиторий

```text
1. github.com → New repository
2. Имя: my-capstone → Public → Create
```

### Шаг 2: Пуш через агента — с одобрением команд

```text
Запушь проект на GitHub:
- git init, добавь все файлы
- commit: «Capstone MVP»
- remote: https://github.com/ТВОЙ_ЛОГИН/my-capstone.git
- push в main

Покажи каждую команду перед выполнением.
```

🚨 Перед `git add .` проверь: в проекте нет `.env` и ключей API? Если есть — попроси агента добавить их в `.gitignore` до пуша. Секреты в публичном репозитории — самая дорогая ошибка новичка.

```bash
git init
git add .
git commit -m "Capstone MVP"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/my-capstone.git
git push -u origin main
```

### Шаг 3: Включи GitHub Pages

```text
1. Репозиторий → Settings → Pages
2. Source: Deploy from a branch
3. Branch: main, /(root) → Save
4. Подожди 2-3 минуты
```

### Шаг 4: Проверь публикацию

```text
1. Открой https://ТВОЙ_ЛОГИН.github.io/my-capstone/ в инкогнито
2. Прогони эвал — приложение работает по ссылке
3. Скинь ссылку другу — у него тоже работает
```

💡 Если деплоить не хочешь — нормально: локальная версия ничем не хуже для себя. Но портфолио (День 5) живёт на ссылках, поэтому демо-ссылка — лучший подарок себе.

## Часть 2: Из чего складывается стоимость агента 🧠

Два счётчика:

```text
Запрос — одно обращение к модели (одна задача в Cline).
Токен — кусочек текста (~3-4 символа): промпт, файлы,
история диалога и ответ — всё считается в токенах.

Бесплатные тарифы ограничивают запросы в минуту и в день,
токены в минуту и в день.
```

### Лимиты бесплатных тарифов

| Провайдер | Бесплатные лимиты |
|-----------|-------------------|
| Groq (`openai/gpt-oss-20b`) | ~30 запросов/мин, ~1000/день, 8K токенов/мин, 200K токенов/день |
| OpenRouter (free-модели) | 20 запросов/мин; 50/день, пока на счету меньше $10, потом до 1000/день; в privacy-настройках отключи обучение на своих данных |
| Gemini AI Studio | бесплатный тариф с дневными лимитами — проверь актуальные на ai.google.dev |
| Ollama локально | лимитов нет: платишь железом и электричеством |

**Проверено: 2026-10-24** (по ADR-0003; лимиты меняются — перепроверяй ежеквартально).

### Прикидка на капстоун

```text
Одна функция = 3-6 запросов (задача + правки после проверки)
Капстоун из 5 функций ≈ 30-60 запросов за неделю разработки
Дневной лимит Groq ~1000 запросов → хватает с большим запасом
```

Настоящая ловушка — не количество запросов, а **8K токенов в минуту**: один запрос с пятью длинными файлами может съесть лимит целиком. Лекарство из недели 3: прикрепляй только нужные файлы.

---

## Часть 3: Как укладываться в лимиты 📉

```text
1. Один запрос = одна маленькая задача (это же лучше для диффов)
2. Контекст по размеру задачи: два нужных файла, не весь проект
3. Длинный диалог → новый диалог: план + файлы + задача
4. Простые задачи → локальная модель (Тир 2), если упёрся в лимит
5. Упёрся в 8K TPM → уменьши контекст или подожди минуту
```

## Часть 4: Учёт — COST.md 🛠️

Cline показывает для каждой задачи израсходованные запросы и токены — смотри в истории задач. Заведи файл:

```markdown
# Стоимость работы агента

## День [N] — [дата]

| Задача | Запросов | ~Токенов | Модель |
|--------|----------|----------|--------|
| Каркас HTML/CSS | 2 | 12K | Groq gpt-oss-20b |
| Функция 1 | 5 | 30K | Groq gpt-oss-20b |
| Функция 2 | 4 | 25K | Groq gpt-oss-20b |

## Вывод
За день: [N] запросов, ~[N]K токенов.
В бесплатный лимит Groq (~1000/день) укладываюсь с запасом.
```

💡 Цифры не должны быть точными до токена. Достаточно порядка: «десятки запросов в день» — и ты уже управляешь стоимостью осознанно, а не наугад.

---

## 🧠 Ключевые принципы

| Принцип | Объяснение |
|---------|------------|
| **Деплой — это просто** | Для статики хватает GitHub Pages, без серверов |
| **Секреты до пуша** | `.gitignore` проверяется перед `git add .` |
| **Запрос ≠ токен** | Лимиты режут и то, и другое — считай оба |
| **Контекст = токены** | Нужные файлы, а не весь проект |
| **Учёт = управление** | COST.md превращает лимиты из страха в цифры |
