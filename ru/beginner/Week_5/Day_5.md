## 🔑 Часть 2: Секреты — что это и где им жить

**Секрет** — всё, что даёт доступ: API-ключ Groq, токен GitHub, пароль базы. Утёкший ключ = чужой доступ от твоего имени.

### Три железных правила:

```text
1. Секрет никогда не попадает в промпт, чат, код или скриншот
2. Секреты живут в .env, .env живёт в .gitignore
3. Утёкший ключ отзывается немедленно — и создаётся новый
```

### Практика: прячем ключ Groq

В корне рабочего проекта создай `.env`:

```bash
GROQ_API_KEY=sk-твой-реальный-ключ
```

И `.gitignore` (если его ещё нет):

```bash
.env
*.local
```

**Проверка:** выполни `git status --short` — файла `.env` в списке быть не должно.

🚨 Если ключ когда-то попал в промпт, скриншот или репозиторий — считай его скомпрометированным: отзови на console.groq.com и выпусти новый.

## ⚙️ Часть 3: Ключи и MCP-серверы

Некоторым серверам нужен свой ключ — он передаётся через блок `env` в `cline_mcp_settings.json`. Пример для поискового сервера:

```json
{
  "mcpServers": {
    "brave-search": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-brave-search"],
      "env": {
        "BRAVE_API_KEY": "твой-ключ"
      },
      "disabled": false,
      "autoApprove": []
    }
  }
}
```

### Честно о рисках:

```text
✅ Файл лежит в настройках VS Code на твоей машине — в репозиторий не попадёт
🚨 Но это обычный текст на диске: не пересылай файл, не снимай его на скриншот
🚨 В уроках, вопросах и ошибках ключи замазывай: BRAVE_API_KEY=***
```

## 🔒 Часть 4: Одобрения — главный тормоз безопасности

За неделю ты видел карточки много раз. Зафиксируем правило на всю карьеру:

```text
Прочитал → Понял → Одобрил.
Не прочитал — не одобрял.
```

- **Сервер** — тот ли это сервер, которому ты доверяешь?
- **Инструмент** — читает (`read`, `list`, `search`) или меняет (`write`, `create`, `delete`)?
- **Аргументы** — путь, SQL, текст: именно это и исполнится.
- **Reject всегда безопасен** — агент просто предложит другой план.

И ещё один переключатель: в настройках авто-одобрения чата Cline держи пункт **MCP-инструменты выключенным**, пока идёшь по курсу. Поле `autoApprove: []` у серверов — пустым.

Скопируй таблицу ниже в новый файл `~/projects/mcp-lab/approval-drill.md` и заполни колонку «Решение» (Approve/Reject + почему одной фразой). Ответы — под таблицей, сначала реши сам.

| 1 | `sqlite (MCP): read_query` → `SELECT * FROM users LIMIT 5;` | |
| 2 | `sqlite (MCP): write_query` → `DELETE FROM orders;` | |

Заполни таблицу, и только потом листай к разбору ниже.

**Проверка:** в `approval-drill.md` — пять строк с решениями и обоснованиями своими словами.

### 💡 Разбор (сравни со своими ответами)

1. **Approve.** `SELECT` только читает, лимит 5 строк.
2. **Reject.** `DELETE` без `WHERE` стирает всю таблицу заказов. Попроси агента объяснить цель — и работать с копией базы.
3. **Approve** после чтения пути: файл новый, внутри лаборатории. Если бы путь указывал на существующий файл — читать дважды.
4. **Reject.** Приватный SSH-ключ вне корня и вне задачи. Такой запрос — стоп в любом виде.
5. **Reject.** Запуск скрипта из интернета без чтения. Сначала прочитай, что он делает.

## 🚨 Часть 5: Красные линии — что агенту не дают никогда

```text
❌ Корень диска /, C:\ или домашнюю папку ~ целиком
❌ Служебные папки: .ssh, .gnupg, .aws, браузерные профили
❌ Рабочие и продакшн-базы — только копии (как test.db)
❌ Секреты в любом виде: в промптах, конфигах без .env, скриншотах
❌ Незнакомые удалённые серверы «на попробовать»
```

### И напомним про локальный vs удалённый:

- **Локальный (stdio)** — данные остаются на твоей машине, но доступ к папке/базе всё равно реальный.
- **Удалённый (HTTP/SSE)** — данные уходят с машины к владельцу сервера. Каждый новый удалённый сервер — это новый человек, которому ты что-то показываешь. Ставь только из официального каталога или Marketplace, читай описание до установки, а не после инцидента.
