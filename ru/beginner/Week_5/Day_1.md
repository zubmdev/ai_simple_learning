## 🎯 Цель дня

Понять, что такое MCP (Model Context Protocol), чем локальные MCP-серверы отличаются от удалённых и почему каждый вызов инструмента в Cline проходит через твоё одобрение.

---

## 🚨 Часть 1: Проблема

### Твой агент в Cline уже умеет:

```text
✅ Читать и писать файлы проекта
✅ Запускать команды в терминале
✅ Следовать правилам из AGENTS.md
```

### Но агент НЕ умеет (без MCP):

```text
❌ Читать базу данных напрямую
❌ Обращаться к внешним сервисам и API
❌ Работать с папками вне твоего проекта
❌ Видеть данные, которые лежат в чужих программах
```

Это как умный помощник, у которого есть пропуск только в одну комнату — в твой проект. Всё остальное здание для него закрыто.

---

## 💡 Часть 2: Аналогия — MCP как USB-порт 📱→🔌

```text
Твой компьютер   = ИИ-агент в Cline
USB-порт         = MCP
Флешка/Мышь/Камера = MCP-серверы (инструменты)
```

**Без USB:** компьютер работает только с тем, что внутри.

**С USB:** подключил флешку → появились файлы; подключил камеру → появилось видео.

**MCP работает так же:**

```text
Без MCP:
ИИ → работает только с текстом и файлами проекта

С MCP:
ИИ → подключён MCP-сервер базы → может читать базу
ИИ → подключён MCP-сервер файлов → может работать с чужой папкой
ИИ → подключён MCP-сервер поиска → может искать в интернете
```

---

## 🧠 Часть 3: Что такое MCP?

**MCP (Model Context Protocol)** — открытый стандарт, который описывает, как агент общается с внешними инструментами. MCP-сервер может дать агенту три вещи:

```text
1. Tools (Инструменты) — агент «действует»
   Примеры: выполнить SQL-запрос, прочитать файл, найти в интернете

2. Resources (Ресурсы) — агент «видит» данные
   Примеры: таблицы базы, содержимое папки, ответ API

3. Prompts (Шаблоны) — готовые сценарии для типовых задач
   Примеры: «проанализируй базу», «сделай отчёт по папке»
```

### Простая схема:

```text
┌─────────────┐
│     Ты      │
│  (промпт)   │
└──────┬──────┘
       ▼
┌─────────────┐         ┌──────────────┐
│   Cline     │ ←─────→ │ MCP-сервер   │
│  (VS Code)  │   MCP   │ (SQLite)     │
└─────────────┘         └──────┬───────┘
                               ▼
                          ┌───────────┐
                          │  test.db  │
                          └───────────┘
```

## 🔌 Часть 4: Два вида серверов: локальные и удалённые

MCP-сервер всегда кто-то запускает. Вопрос только — где.

| | Локальный сервер | Удалённый сервер |
|---|---|---|
| **Где работает** | На твоей машине (Cline запускает его сам) | На серверах разработчика |
| **Как подключается** | Через stdin/stdout — Cline стартует процесс | По сети (HTTP/SSE), по адресу-URL |
| **Куда попадают данные** | Данные не покидают твой компьютер | Запросы и данные уходят вовне |
| **Что нужно установить** | Рантайм: Node.js или Python | Ничего — только адрес и иногда токен |
| **Чему ты доверяешь** | Коду сервера и тому, к чему дал доступ | Коду сервера + его владельцу |

**Честно про оба варианта:**

- «Локальный» не значит «безопасный автоматически». Локальный сервер всё равно может читать и менять то, к чему ты дал доступ. Он лишь не отправляет данные на сторону.
- «Удалённый» не значит «плохой». Но каждый удалённый сервер — это новый человек или компания, которым ты показываешь часть своих данных.

До Дня 5 мы будем работать только с локальными серверами — это самый честный способ разобраться в механике.

## 🗂️ Часть 5: Какие MCP-серверы бывают

| MCP-сервер | Что даёт агенту | Тип |
|------------|-----------------|-----|
| **File System** | Чтение и запись файлов в одной разрешённой папке | Локальный |
| **SQLite** | Запросы к локальной базе данных | Локальный |
| **Memory** | Память между диалогами (заметки о проекте) | Локальный |
| **GitHub** | Работа с репозиториями и issues | Удалённый |
| **Brave Search** | Поиск в интернете | Удалённый |

Каталог серверов: `github.com/modelcontextprotocol/servers` и вкладка Marketplace прямо в Cline — с ней познакомимся завтра.

## 🔒 Часть 6: Одобрения — предохранитель MCP

Инструменты — это действия в реальном мире: запрос к базе, запись файла, звонок в API. Поэтому в Cline действует правило:

```text
Любой вызов MCP-инструмента по умолчанию требует твоего одобрения.
```

Перед каждым вызовом Cline показывает карточку: **какой сервер**, **какой инструмент**, **с какими аргументами**. Ты читаешь — и решаешь: Approve или Reject. На этой неделе ты научишься читать такие карточки за пару секунд.

## 🛠️ Часть 7: Что понадобится

| Уровень | Железо | Модель в Cline |
|---------|--------|----------------|
| CPU + бесплатный API | любой компьютер | Groq `openai/gpt-oss-20b` |
| 4GB GPU (Ollama) | видеокарта от 4GB VRAM | `qwen3.5:2b` (запасная: `qwen3:4b`) |
| 16GB GPU (Ollama) | видеокарта от 16GB VRAM | `gpt-oss:20b` |

**Проверено: 2026-10-24.** Ничего нового ставить не нужно: всё уже настроено в Неделе 1.

💡 MCP-инструменты — это «вызов функций», и небольшие локальные модели справляются с ними хуже, чем облачные. Если на 4GB-модели агент путается в инструментах — это нормально; для этой недели удобнее уровень CPU+API или 16GB.

## 🧠 Ключевые принципы

| Принцип | Объяснение |
|---------|------------|
| **MCP = USB-порт** | Стандарт для подключения инструментов к агенту |
| **Tools, Resources, Prompts** | Действовать, видеть, следовать сценариям |
| **Локальный vs удалённый** | Данные остаются у тебя или уходят вовне |
| **Одобрение по умолчанию** | Каждый вызов инструмента — только через твоё «Да» |
