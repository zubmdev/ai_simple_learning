## 🧠 Часть 2: Принцип наименьших привилегий

**Least privilege** — давай ровно столько доступа, сколько нужно для задачи, и ни байтом больше.

Аналогия: пропуск в офис. Уборщице не нужен доступ в серверную, а тебе — в кабинет директора. Мастер-ключ удобнее, но если его украдут, украдут всё.

Для файлового MCP это значит: у сервера есть **один корневой каталог** (`root`), и за его пределы инструменты сервера не выходят физически.

💡 Честное замечание: для файлов внутри текущего проекта Cline и так умеет читать и писать — MCP тут не нужен. Файловый сервер нужен для папок **вне проекта** (отчёты, данные, чужие каталоги) — и это идеальный полигон, чтобы понять механику ограничений.

## ⚙️ Часть 4: Подключаем сервер с ограниченным корнем

Открой `cline_mcp_settings.json` и добавь сервер `filesystem`:

```json
{
  "mcpServers": {
    "memory": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-memory"],
      "env": {},
      "disabled": false,
      "autoApprove": []
    },
    "sqlite": {
      "command": "uvx",
      "args": ["mcp-server-sqlite", "--db-path", "/home/username/projects/mcp-lab/test.db"],
      "env": {},
      "disabled": false,
      "autoApprove": []
    },
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/home/username/projects/mcp-lab"],
      "env": {},
      "disabled": false,
      "autoApprove": []
    }
  }
}
```

Последний элемент `args` — и есть **корень доступа**. Замени на свой абсолютный путь. Windows: `"C:\\Users\\name\\projects\\mcp-lab"`.

### Правила корня:

```text
✅ Отдельная папка для экспериментов (mcp-lab, папка одного проекта)
❌ Корень диска  /  или  C:\
❌ Домашняя папка целиком (~)
❌ Служебные папки: .ssh, .gnupg, .aws
❌ Папки с паролями, ключами, рабочими документами
```

Сохрани конфиг, убедись, что `filesystem` зелёный.

## ✅ Часть 5: Проверка границ — и живой отказ

### Тест 1: внутри корня (должно работать)

```text
Покажи список файлов в папке mcp-lab и прочитай notes.md.
```

Карточки: `filesystem (MCP): list_directory` и `read_file` — пути внутри корня → **Approve**.

### Тест 2: снаружи корня (должен быть отказ)

```text
Прочитай файл ~/.bashrc через файловый сервер.
```

Что произойдёт: агент попытается вызвать `read_file` с путём вне корня — и **сервер вернёт ошибку** «access denied / path outside allowed directories». Это не поломка — это ограничение, которое ты сам настроил. Запиши текст ошибки.

### Тест 3: честная проверка предохранителя

🚨 Ограничение защищает только инструменты **этого сервера**. Тот же агент всё ещё может предложить прочитать `~/.bashrc` через терминал (`cat ~/.bashrc`) — но это будет **отдельная карточка одобрения**, где путь виден так же явно. Вывод недели: граница + читаемые карточки работают в паре. Ни одну карточку не пропускай «на автопилоте».

---

## 🧠 Часть 6: Что умеет файловый сервер

| Инструмент | Действие | Что проверить в карточке |
|------------|----------|--------------------------|
| `list_directory` | Показать содержимое папки | Папка внутри корня? |
| `read_file` | Прочитать файл | Путь и размер — то, что просил? |
| `write_file` | Создать/перезаписать файл | КУДА пишет и что перезапишет? |
| `search_files` | Поиск по имени | Область поиска внутри корня? |

Самый опасный — `write_file`: он может **перезаписать** существующий файл. Читай путь особенно внимательно.

## 🔧 Часть 7: Troubleshooting

| Симптом | Что делать |
|---------|------------|
| Сервер не стартует | Проверь `node --version`; лог ошибки — в окне MCP |
| Ошибка на каждый запрос | Путь корня в `args` не существует или с опечаткой — проверь `ls` |
| «Access denied» на валидный файл | Файл вне корня — так и задумано: перенеси его в mcp-lab, если он нужен |
| Слишком много серверов в списке | Ненужные выключай: `"disabled": true` — настройка останется |

---

## 🧠 Ключевые принципы

| Принцип | Объяснение |
|---------|------------|
| **Least privilege** | Один корень, ровно нужный доступ |
| **Отказ — это работа** | Ошибка «вне корня» означает, что защита работает |
| **Граница ≠ вся защита** | Терминальные команды одобряются отдельными карточками |
| **write_file опаснее read_file** | Перезапись необратима — путь читай дважды |
