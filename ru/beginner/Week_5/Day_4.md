## Часть 1: Как работает диалог с MCP?

### Магия автоматического распознавания

```
Ты: "Покажи всех пользователей"

ИИ (автоматически):
1. Понимает: нужен доступ к базе
2. Проверяет: есть ли MCP SQLite?
3. Вызывает: list_tables → describe_table → read_query
4. Форматирует: показывает красивый результат
```

**Тебе НЕ нужно говорить "используй MCP"** — ИИ сам решает, какие инструменты применить.

## Часть 3: Практика — Реальные запросы

### Запрос 1: Анализ пользователей

```
Твой промпт:
"Проанализируй таблицу users и скажи:
1. Сколько всего пользователей?
2. Когда создан последний?
3. Есть ли дубликаты email?"
```

**Что делает ИИ (автоматически):**

```sql
-- 1. Количество
SELECT COUNT(*) FROM users;

-- 2. Последний созданный
SELECT MAX(created_at) FROM users;

-- 3. Дубликаты email
SELECT email, COUNT(*) as count 
FROM users 
GROUP BY email 
HAVING count > 1;
```

**Результат:**

```

1. Всего пользователей: 5
2. Последний создан: 2024-01-15 10:30:00
3. Дубликаты email: не найдены

✅ База в хорошем состоянии!
```

### Запрос 2: Анализ заказов

```
Твой промпт:
"Проанализируй таблицу orders и составь отчёт:
- Общая сумма всех заказов
- Самый дорогой заказ
- Самый популярный товар
- Топ-3 покупателя по сумме заказов"
```

**Что делает ИИ:**

```sql
-- Общая сумма
SELECT SUM(amount) FROM orders;

-- Самый дорогой
SELECT * FROM orders ORDER BY amount DESC LIMIT 1;

-- Самый популярный
SELECT product, COUNT(*) as count 
FROM orders 
GROUP BY product 
ORDER BY count DESC 
LIMIT 1;

-- Топ-3 покупателя
SELECT u.name, SUM(o.amount) as total
FROM users u
JOIN orders o ON u.id = o.user_id
GROUP BY u.id
ORDER BY total DESC
LIMIT 3;
```

**Результат:**


### Запрос 3: Генерация кода на основе данных

```
Твой промпт:
"Прочитай структуру базы test.db и напиши Python скрипт,
который:
1. Подключается к этой базе
2. Создаёт класс User с полями из таблицы users
3. Добавляет метод для получения заказов пользователя"
```

**Что делает ИИ:**

1. Читает структуру через MCP
2. Генерирует код:

```python
import sqlite3
from dataclasses import dataclass
from typing import List
from datetime import datetime

@dataclass
class User:
    id: int
    name: str
    email: str
    created_at: datetime
    
    @classmethod
    def from_db(cls, row: tuple) -> 'User':
        return cls(
            id=row[0],
            name=row[1],
            email=row[2],
            created_at=datetime.fromisoformat(row[3])
        )
    
    def get_orders(self, db_path: str = 'test.db') -> List[dict]:
        """Получить все заказы пользователя."""
        conn = sqlite3.connect(db_path)
        cursor = conn.cursor()
        cursor.execute(
            "SELECT * FROM orders WHERE user_id = ?",
            (self.id,)
        )
        orders = cursor.fetchall()
        conn.close()
        return orders

def get_user_by_id(user_id: int, db_path: str = 'test.db') -> User:
    """Получить пользователя по ID."""
    conn = sqlite3.connect(db_path)
    cursor = conn.cursor()
    cursor.execute("SELECT * FROM users WHERE id = ?", (user_id,))
    row = cursor.fetchone()
    conn.close()
    return User.from_db(row) if row else None

# Пример использования
if __name__ == "__main__":
    user = get_user_by_id(1)
    print(f"Пользователь: {user.name}")
    print(f"Email: {user.email}")
    print(f"Заказы: {len(user.get_orders())}")
```

### Анализ временных рядов

```
Твой промпт:
"Если бы в таблице orders была дата (order_date), 
покажи как бы выглядел запрос для:
- Заказов по дням
- Рост по неделям
- Лучший день недели для продаж"
```

ИИ покажет SQL шаблоны:

```sql
-- Заказы по дням
SELECT DATE(order_date) as date, COUNT(*) as orders
FROM orders
GROUP BY DATE(order_date)
ORDER BY date;

-- Рост по неделям
SELECT 
    strftime('%Y-%W', order_date) as week,
    COUNT(*) as orders,
    LAG(COUNT(*)) OVER (ORDER BY strftime('%Y-%W', order_date)) as prev_week
FROM orders
GROUP BY strftime('%Y-%W', order_date);

-- Лучший день недели
SELECT 
    strftime('%w', order_date) as day_of_week,
    COUNT(*) as orders
FROM orders
GROUP BY strftime('%w', order_date)
ORDER BY orders DESC
LIMIT 1;
```

## Часть 5: Ошибки и как их избегать

### ❌ Ошибка 1: Слишком абстрактный запрос

```
Плохо: "Что там в базе?"
Хорошо: "Покажи список всех таблиц и количество записей в каждой"
```

### ❌ Ошибка 2: Нет контекста

```
Плохо: "Покажи пользователей"
Хорошо: "Покажи всех пользователей из таблицы users, отсортированных по дате создания"
```

### ❌ Ошибка 3: Несуществующие данные

```
Плохо: "Найди пользователей из Москвы" 
(в базе нет поля city)

Хорошо: Сначала спроси: "Какие поля есть в таблице users?"
```

### ✅ Правильный подход:

```
1. Сначала изучи структуру: "Покажи схему таблицы users"
2. Потом задавай конкретные вопросы
3. Если не уверен — спроси: "Какие данные доступны?"
```
