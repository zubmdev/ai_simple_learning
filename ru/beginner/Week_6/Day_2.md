# День 2: Scaffolding — Создаём каркас проекта 🏗️

**Трек:** 🌱 Начинающий | **Время:** 45 минут

---

## 🎯 Цель дня

Создать каркас проекта руками агента: файлы, базовую структуру и AGENTS.md — и при этом контролировать каждый его шаг.

---

## Часть 1: Что такое Scaffolding?

**Scaffolding** — создание «скелета» проекта:

```
📦 Создаём:
- Пустые файлы с базовой структурой
- Комментарии-заглушки (TODO) для будущих шагов
- README с описанием
- AGENTS.md — правила работы агента в этом проекте

❌ НЕ создаём:
- Полную логику
- Дизайн
- Готовые фичи
```

### 💡 Аналогия

Scaffolding — это фундамент и каркас стен дома. Ты ещё не строишь дом, но разметка уже стоит: видно, где что будет. Заполнением займёмся в Дне 3–4 — по одной комнате за раз.

---

## Часть 2: Каркас через агента

### Шаг 1: Один запрос — весь каркас

Открой Cline в папке проекта (там уже лежит PLAN.md) и напиши:

```text
Прочитай PLAN.md. Создай в проекте файлы по плану:
- index.html — каркас страницы: заголовок «To-Do App», подключение
  styles.css и app.js, комментарии, что где будет
- styles.css — сброс отступов и комментарии-секции (БЕЗ дизайна)
- app.js — пустые функции addTask, toggleTask, deleteTask
  с комментариями (БЕЗ реализации)
- README.md — название, описание, структура файлов, как запустить

Кода-реализации пока не пиши, только структуру и TODO.
```

### Шаг 2: 🚨 Одобри команды терминала

Для создания файлов Cline предложит команды вроде `mkdir` и `touch` — и спросит разрешение перед каждым запуском:

```bash
mkdir -p todo-app
cd todo-app && touch index.html styles.css app.js README.md
```

**Держи одобрения включёнными.** Каждую команду читай перед одобрением:

- Команда создаёт файлы в папке проекта? → Approve.
- Команда удаляет, перезаписывает что-то вне проекта или выглядит странно? → Reject и спроси агента, зачем она.

Это минимальные привилегии в действии: агенту нужен доступ к папке проекта, а не ко всему диску.

### Шаг 3: Diff-ревью созданных файлов

После выполнения Cline покажет diff'ы — что в каких файлах появилось. Прежде чем идти дальше:

1. Открой `index.html` — есть подключение `styles.css` и `app.js`?
2. Открой `app.js` — есть имена функций из плана: `addTask`, `toggleTask`, `deleteTask`?
3. Открой `README.md` — описание совпадает с PLAN.md?

Что-то не так — не исправляй руками. Скажи агенту: «В app.js нет функции deleteTask, добавь заглушку». Руками ты вообще не пишешь — только проверяешь и направляешь.

## Часть 3: AGENTS.md — правила проекта

Каркас — лучший момент создать AGENTS.md: файл с правилами, которые агент читает в начале каждой задачи, чтобы ты не повторял их в каждом запросе.

### Промпт:

```text
Создай файл AGENTS.md для этого проекта:
- Что это за проект (кратко, из PLAN.md)
- Структура файлов и за что каждый отвечает
- Правила работы: код с комментариями на русском;
  менять только файл, о котором попросили;
  после каждого изменения писать, как мне проверить результат
- Технологии: HTML/CSS/JavaScript, localStorage

Прочитай PLAN.md и AGENTS.md и подтверди, что понял проект.
```

### Пример AGENTS.md:

```markdown
# To-Do App

Простое веб-приложение для управления задачами. Владелец проекта —
начинающий, код руками не пишет: агент делает, человек проверяет.

## Структура
- index.html — страница: форма + список задач
- styles.css — внешний вид
- app.js — логика (addTask, toggleTask, deleteTask, localStorage)
- PLAN.md — план разработки с критериями приёмки

## Правила
- Меняем только файл, о котором попросили
- Каждое изменение сопровождаем инструкцией «как проверить»
- Одна задача за раз: не трогаем то, что не просили
- Комментарии в коде на русском

## Технологии
HTML5, CSS3, JavaScript (ES6+), localStorage.
```

### Проверка, что AGENTS.md работает:

```text
Без чтения файлов: какую структуру имеет этот проект и какие
правила ты обязан соблюдать?
```

Агент отвечает по AGENTS.md, а не выдумывает — правила подхватились.

## Часть 4: Проверка каркаса

### Финальный тест дня:

```text
Проверь каркас проекта против PLAN.md:
1. Все ли файлы из плана созданы?
2. Правильно ли index.html подключает styles.css и app.js?
3. Чего не хватает?
```

### Самостоятельная проверка (важнее ответа агента):

```
1. Открой index.html в браузере (двойной клик)
2. Что видишь: пустая страница с заголовком «To-Do App» — каркас работает
3. Нажми F12 → вкладка Console: нет красных ошибок — связи не сломаны
```

### 💡 Если страница пустая или ошибки в консоли

Не откатывай руками. Скопируй текст ошибки из консоли в Cline:

```text
Открываю index.html — страница пустая. В консоли ошибка:
(вставь текст ошибки из F12)
Найди причину и исправь. Сначала объясни, что сломано.
```

Проверка: скрин дерева проекта в Cline и чистая консоль (F12) — каркас работает.

**Путь B (creator):** Создай структуру проекта ролика: папки `scenario/`, `storyboard/`, `frames/`, `audio/`, `edit/`, а внутри `edit/` — файл `project-notes.md` с планом монтажа (порядок кадров, длительность каждого). Проверка: по `project-notes.md` видно, какие файлы лягут в монтаж и в каком порядке.
