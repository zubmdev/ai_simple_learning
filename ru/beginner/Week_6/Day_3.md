## 🎯 Цель дня

Реализовать первую фичу приложения через агента — по циклу «одна задача → diff-ревью → проверка». И повторить цикл на следующих фичах.

## Часть 1: Правило одной задачи

### Золотое правило недели:

```
ОДНА ЗАДАЧА = ОДИН ЗАПРОС К АГЕНТУ = ОДНА ПРОВЕРКА

❌ Плохо:  «Сделай всё приложение сразу»
✅ Хорошо: «Задача 3 из PLAN.md: логика добавления задачи.
           Ничего кроме app.js не меняй»
```

### Почему так?

```
✅ Меньше ошибок — агент не распыляется
✅ Diff маленький — его реально прочитать
✅ Проверка простая — один критерий приёмки
✅ Откат дешёвый — не принял один diff, остальное цело
```

💡 Если диф вырос на сотни строк — останови агента и попроси разбить задачу. Читать и проверять большой диф ты всё равно не будешь, а непроверенный код — это не твой код.

## Часть 2: Фича 1 — содержимое страницы

### Запрос (одна задача из PLAN.md):

```text
Задача из PLAN.md: наполнение index.html.

Добавь в index.html:
1. Заголовок <h1> «Мои задачи»
2. Форму: поле ввода (id="task-input") и кнопка «Добавить»
3. Пустой список <ul id="task-list">

Форму и список оберни в <div class="container">.
id нужны ровно такие — они понадобятся app.js завтра.
Другие файлы не трогай.
```

### Diff-ревью перед одобрением:

Cline покажет изменения в index.html. Прочитай диф и сверь:

- [ ] Есть все три элемента: заголовок, форма, список?
- [ ] `id="task-input"` и `id="task-list"` — ровно как в запросе?
- [ ] styles.css и app.js **не** тронуты (нет лишних дифов)?

Совпало — Approve. Нет — отклони и уточни: «Не меняй styles.css, только index.html».

### Проверка (критерий приёмки):

```
Открой index.html в браузере.
Ожидаю: заголовок, поле ввода, кнопка, пустой список.
Некрасиво — и нормально: стили отдельная задача.
```

Шаг закрыт. Запиши прогресс: «задача 1 — ✅» в PLAN.md (можно попросить агента).

## Часть 3: Повторяем цикл — остальные фичи

Дальше тот же цикл. Для каждой фичи — запрос, diff-ревью, проверка. Между фичами страница перезагружается и проверяется.

### Фича 2 — стили:

```text
Задача из PLAN.md: стили в styles.css.

Требования:
- Контейнер по центру, белая карточка с тенью
- Поле ввода и кнопка в один ряд, на мобильном — в столбец
- Светлый фон, один акцентный цвет

Проверю: обновлю страницу — аккуратная карточка по центру.
```

**Проверка:** сузь окно браузера до ширины телефона — форма перестраивается в столбец.

### Фича 3 — добавление задачи:

```text
Задача из PLAN.md: логика добавления в app.js.

1. При отправке формы — добавить задачу в список
2. Каждая задача: текст, чекбокс, кнопка «Удалить»
3. После добавления поле ввода очищается

Сохранение в localStorage пока НЕ делай — это отдельная задача.
```

**Проверка:** ввожу «Купить хлеб» → задача в списке. Отмечаю чекбокс → текст зачёркивается. Удаляю → исчезает. **Перезагружаю страницу → задачи пропали.** Это ожидаемо: сохранение — следующая задача.

### Фича 4 — сохранение:

```text
Задача из PLAN.md: сохранение в localStorage.

1. После каждого изменения списка — сохранять задачи
2. При открытии страницы — загружать сохранённые
3. Ключ: 'todo_tasks'
```

**Проверка (та же, что час назад, но с другим исходом):** добавь две задачи → перезагрузи страницу → **задачи на месте**. Сверься с PLAN.md: критерий «делаю X — вижу Y» выполнен.

### 🚨 Если проверка провалилась

Не проси «сделай заново». Опиши, что видишь:

```text
Добавляю задачу — ничего не происходит.
В консоли (F12): ReferenceError: addTask is not defined.
Найди причину. Сначала объясни, потом исправляй.
```

Ошибка из консоли — лучший контекст для агента: с ней он чинит за один шаг.

## 🎯 Миссия дня

**Путь A (кодинг):** Все 4 фичи MVP работают: добавление, отметка, удаление, сохранение после перезагрузки. PLAN.md обновлён — каждая задача помечена выполненной. Проверка: пройди по критериям приёмки из Дня 1 один за другим — каждый «делаю X» даёт свой «вижу Y».

**Путь B (creator):** Сгенерируй первый кадр по сториборду. Если 16GB GPU — локально в ComfyUI (Stable Diffusion или Flux); если CPU или 4GB GPU — через бесплатный облачный генератор. Сохрани кадр в `frames/` под именем `frame-01.png` и рядом `frame-01-prompt.txt` с текстом промпта. Проверка: кадр соответствует описанию из сториборда, промпт записан — кадр можно воспроизвести.
