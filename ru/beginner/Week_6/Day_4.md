## Часть 1: Контекст — что агент видит

### 💡 Аналогия

Агент — новый сотрудник, который каждый день приходит на работу с чистой памятью. Контекст — это то, что лежит у него на столе. Дашь нужные бумаги — сделает правильно. Дашь лишние — утонет в них. Не дашь ничего — будет угадывать.

### Три способа дать контекст в Cline:

```
1. AGENTS.md — агент читает его сам в начале задачи.
   Правила проекта и структура живут здесь (День 2).
2. Явное имя файла в запросе: «Открой app.js и styles.css…»
3. Прикрепление файла через @ в поле ввода Cline —
   файл гарантированно попадёт в контекст.
```

### Правило дня:

```
Однострочное изменение  → AGENTS.md достаточно
Затрагивает 1 файл      → назови файл
Затрагивает 2+ файла    → назови ВСЕ файлы и роль каждого
```

### Проверка понимания (1 минута):

```
Ответь своими словами:
1. Куда агент смотрит за правилами проекта?
2. Что даст агенту, если попросить «добавь счётчик», не назвав файлов?
3. Почему для уведомлений нужно назвать и index.html, и app.js?
```

## Часть 2: Улучшение с контекстом — уведомления

Эта фича затрагивает три файла — идеальный кандидат на явный контекст.

### Запрос:

```text
Улучшение: всплывающие уведомления.

Файлы: app.js (логика), styles.css (оформление).

Сделай:
1. Функция showNotification(message) в app.js: зелёная плашка
   вверху экрана, исчезает через 2 секунды
2. Вызовы: при добавлении задачи — «Задача добавлена!»,
   при удалении — «Задача удалена»
3. Стили плашки — в styles.css, не инлайном кодом

index.html не меняй — уведомление создаётся из JS.
После изменения напиши, как мне проверить результат.
```

### Diff-ревью:

- [ ] Изменены ровно два файла из запроса — app.js и styles.css?
- [ ] `index.html` остался нетронутым?
- [ ] Функция называется `showNotification`, вызовы там, где просили?

**Проверка:** добавь задачу — зелёная плашка появилась и исчезла через 2 секунды. Удали — вторая плашка. Критерий закрыт.

## Часть 3: Ещё два улучшения — тренируйся сам

Формат тот же: запрос с контекстом → diff-ревью → проверка.

### Улучшение 1 — счётчик задач (2 файла):

```text
Улучшение: счётчик задач.

Файлы: index.html, app.js.
В index.html под заголовком — блок со строками
«Всего: N» и «Выполнено: N» (id: total-count, completed-count).
В app.js — функция updateStats(), вызывается при каждом
изменении списка. Стили не трогай.
```

**Проверка:** добавь три задачи, две отметь — счётчики показывают «Всего: 3» и «Выполнено: 2» и обновляются дальше.

### Улучшение 2 — подтверждение удаления (1 файл):

```text
Улучшение: подтверждение удаления.

Файл: app.js. Перед удалением — стандартный confirm
«Удалить задачу "(текст)"?». Отмена — ничего не удаляем.
```

**Проверка:** жмёшь «Удалить» → вопрос появляется; «Отмена» — задача остаётся.

## Часть 4: Когда агент ошибается

### Сценарий: попросили кнопку «Очистить всё» — кнопка есть, не работает.

Диагноз почти всегда один: изменение коснулось HTML, но не коснулось JS (или наоборот). Контекст был неполный.

### Как чинить — через контекст, а не через угадывание:

```text
Кнопка «Очистить всё» (id="clear-all") в index.html не работает.

Файлы: index.html (там кнопка), app.js (обработчик должен быть там).
Проверь цепочку: кнопка → обработчик → действие.
Найди, где цепочка рвётся, объясни и почини.
```

Агент читает оба файла, находит разрыв (кнопка есть — обработчика нет) и добавляет недостающий код.

### 💡 Урок

Ошибка агента чаще всего = ошибка контекста. Прежде чем писать «не работает», проверь себя: все ли затронутые файлы названы? Чинить дёшево, когда контекст полный; дорого — когда агент угадывает.

## Часть 5: Рефакторинг — улучшаем код без изменения поведения

### Запрос:

```text
Файл: app.js.

Проведи рефакторинг: вынеси повторяющиеся селекторы в константы,
добавь проверку, что текст задачи не пустой и не длиннее 200 символов.

ВАЖНО: поведение не меняется. Все фичи работают как раньше.
После рефакторинга скажи, как мне это проверить.
```

### 🚨 Diff-ревью рефакторинга — обязателен

Рефакторинг — самое коварное изменение: выглядит безобидно, ломает незаметно. Читай диф внимательно:

- Появились новые функции, которых ты не просил? → Отклони, уточни.
- Изменились имена функций (`addTask` → `add`)? → Отклони: имена из AGENTS.md.
- Только выделение констант и валидация? → Одобряй.

**Проверка после рефакторинга — та же, что в Дне 3:** добавление, отметка, удаление, сохранение после перезагрузки, пустой текст не добавляется. Всё работает — рефакторинг безопасен. Что-то сломалось — скажи агенту, какая проверка провалилась, и откатись: Cline умеет вернуть файл к предыдущему состоянию (кнопка отката у дифа).

## Часть 6: Фиксируем историю

```text
Создай CHANGELOG.md: секция [1.0.0] со списком всего,
что сделано за неделю: фичи MVP, уведомления, счётчик,
подтверждение удаления, рефакторинг.
Формат: Added / Changed.
```

Этот файл — твоя память о проекте. Через месяц ты забудешь, что делал в четверг; CHANGELOG — нет.
