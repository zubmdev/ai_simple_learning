# День 1: Планирование через диалог — Архитектура проекта 📋

**Трек:** 🌱 Начинающий | **Время:** 40 минут

---

## 🎯 Цель дня

Выбрать проект недели и превратить идею в план с критериями приёмки. К концу дня у тебя будет файл PLAN.md, по которому агент будет работать всю неделю.

---

## Часть 1: Выбери путь недели

У недели два проекта на выбор. Путь не меняется до конца недели — выбери один.

### Путь A: Кодинг-проект (основной) 💻

Ты строишь маленькое работающее приложение через агента в Cline. Варианты для новичка:

#### Вариант: To-Do веб-приложение ✅ (рекомендуем)

**Что делает:**
- Добавлять задачи
- Отмечать выполненные
- Хранить задачи в браузере

**Сложность:** ⭐

**Технологии:** HTML/CSS, JavaScript, localStorage

**Альтернативы:** Telegram-бот (⭐⭐) или конвертер валют (⭐⭐), если To-Do кажется слишком простым.

### Путь B: Creator module (альтернативный проект недели) 🎬

Ты собираешь короткий ролик (30–60 секунд) по одному пайплайну:

```
идея → сценарий → сториборд → генерация изображения/видео
     → озвучка → монтаж → публикация
```

Инструменты FOSS: ComfyUI + Stable Diffusion/Flux (кадры), FFmpeg (обработка), Whisper и Piper (озвучка и субтитры), Kdenlive (монтаж). По дням недели это ложится так: День 1 — сценарий и сториборд, День 2 — структура проекта, День 3 — генерация кадров, День 4 — озвучка и монтаж, День 5 — публикация.

**Честно про железо** (проверено: 2026-10-24):

| Твой уровень | Генерация кадров | Озвучка и субтитры | Монтаж |
|---|---|---|---|
| CPU + бесплатные облачные генераторы | через бесплатные API/демо Stable Diffusion или Flux | Whisper (tiny/base) и Piper локально, работает на CPU | Kdenlive или FFmpeg |
| 4GB GPU | ⚠️ ComfyUI с современными моделями скорее всего не влезет — используй облачные бесплатные API для кадров | Whisper small, Piper — без проблем | Kdenlive |
| 16GB GPU | ComfyUI + Stable Diffusion/Flux локально, короткие видеоклипы | Whisper, Piper | Kdenlive |

Генерация изображения и видео — самая тяжёлая часть пайплайна. Если у тебя CPU или 4GB GPU — честный путь: кадры генерируешь в облаке (бесплатные лимиты), а озвучку, субтитры и монтаж делаешь локально.

**Этика Creator-пути (обязательная часть модуля):**
- **Согласие:** не используй лица и голоса реальных людей без их разрешения.
- **Авторское право:** не генерируй узнаваемых персонажей, логотипы и чужую музыку.
- **Раскрытие:** помечай опубликованный ролик как созданный с помощью ИИ.
- **Без имитации:** никаких deepfake-подделок под реальных людей.

> 🚨 Creator-инструменты не смешиваются с кодинг-настройкой. Если выбрал Путь A — creator-разделы игнорируй, они встретятся только в вариантах миссий.

## Часть 2: Проверь оснастку агента (Путь A)

Для недели нужен работающий агент в VS Code. Если что-то из этого не настроено — вернись к Неделе 1.

| Уровень | Чем работаешь | Модель |
|---|---|---|

| 16GB GPU + Ollama | VS Code + Cline, Ollama | `gpt-oss:20b` |

Открой Cline в VS Code и напиши:

```
Ответь одним словом: готов?
```

Агент ответил — оснастка работает. Дальше — планирование.

## Часть 3: Первый диалог — описание идеи

### 💡 Что такое критерий приёмки

Критерий приёмки — это предложение вида «делаю X — вижу Y». Не «красивое приложение», а «открываю файл — вижу заголовок и форму». Критерии превращают план из пожеланий в чеклист, который ты можешь проверить. Всё, что нельзя проверить, — слишком расплывчато для агента.

### Промпт в Cline:

```text
Я хочу создать To-Do веб-приложение. Мой уровень: начинающий.
Работаю через агента в Cline, код вручную не пишу.

Помоги спланировать проект:
1. Какие функции войдут в MVP (минимум, без излишеств)?
2. Какие файлы понадобятся?
3. Для каждой функции — критерий приёмки в формате «делаю X — вижу Y».
4. Порядок разработки: какая функция первая?

Пока НЕ пиши код. Только план.
```

### Пример ответа агента:

```text
План MVP To-Do приложения:

Функции и критерии приёмки:
1. Добавление задачи — ввожу текст, нажимаю «Добавить»,
   задача появляется в списке.
2. Отметка выполнения — нажимаю чекбокс, текст зачёркивается.
3. Удаление — нажимаю «Удалить», задача исчезает.
4. Сохранение — перезагружаю страницу, задачи на месте (localStorage).

Файлы:
- index.html  — страница: форма + список
- styles.css  — внешний вид
- app.js      — логика
- README.md   — описание проекта

Порядок: каркас → добавление → отметка/удаление → сохранение.
```

### Задай уточняющие вопросы:

```text
Добавь в план: редактирование задачи и фильтр «только невыполненные».
Это для MVP или на потом? Объясни почему.
```

Хороший агент честно скажет: для MVP это лишнее, вынеси в v2. Не спорь — меньше функций, быстрее результат. Уточнения фиксируем в плане.

## Часть 4: Сохраняем план в PLAN.md

Теперь от разговора — к артефакту. Попроси агента записать план в файл:

```text
Создай папку проекта todo-app и в ней файл PLAN.md с нашим планом:
- Цель проекта
- Функции MVP с критериями приёмки
- Список файлов
- Порядок разработки
- Секция «Что на потом» (v2.0)

Покажи мне содержимое файла перед сохранением.
```

### 🚨 Первый diff-ревью недели

Cline покажет, что именно он собирается создать, и попросит одобрение. Не жми Approve вслепую:

1. Прочитай содержимое файла в превью.
2. Сверь с договорённостями: все функции? критерии на месте?
3. Совпадает — одобри. Нет — напиши, что поправить: «Убери функцию X из MVP, добавь критерий для сохранения».

Одобрение diff'а — навык, который ты тренируешь всю неделю.

## Часть 5: Разбивка на задачи

Финальный шаг планирования — превратить план в короткие задачи для агента:

```text
Разбей разработку на задачи по плану. Для каждой задачи:
- Что делаем (одна функция или один файл)
- Критерий приёмки
- Как я проверю результат сам

Добавь этот список в конец PLAN.md. Одну задачу должно быть
можно выполнить за один твой запрос к агенту.
```

Пример результата:

```text
Задача 1: Каркас — index.html со структурой страницы.
  Проверка: открываю файл в браузере — вижу заголовок и пустую форму.
Задача 2: Стили — styles.css.
  Проверка: страница выглядит аккуратно, форма по центру.
Задача 3: Логика добавления — app.js, функция addTask.
  Проверка: ввожу текст — задача появляется в списке.
Задача 4: Отметка и удаление.
  Проверка: чекбокс зачёркивает, кнопка удаляет.
Задача 5: Сохранение в localStorage.
  Проверка: перезагрузка страницы — задачи на месте.
```

## 🎯 Миссия дня

**Путь A (кодинг):** Получи в проекте файл PLAN.md, в котором есть: цель, минимум 3 функции MVP, у каждой — критерий приёмки в формате «делаю X — вижу Y», и список из 5 задач разработки. Проверка: открой PLAN.md и пройдись по чеклисту — каждый критерий можно проверить без кода.

**Путь B (creator):** Напиши в файле `scenario.md` сценарий ролика на 30–60 секунд (3–5 кадров) и рядом к каждому кадру — описание картинки одним предложением (это и есть сториборд). Проверка: читаешь сценарий — по нему можно нарисовать каждый кадр, не задавая вопросов.
