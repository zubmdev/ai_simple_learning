## Часть 1: Что такое MVP?

```
MVP (Minimum Viable Product) =
минимально жизнеспособный продукт

Работает, им можно пользоваться. Без излишеств.
```

```
MVP для To-Do:
✅ Добавлять задачи
✅ Отмечать выполненными
✅ Удалять задачи
✅ Сохранять в браузере

НЕ MVP (это v2.0):
❌ Категории и фильтры
❌ Редактирование задач
❌ Аккаунты и база данных
```

Если что-то из «НЕ MVP» уже работает — отлично, но не добавляй новое сегодня. Сегодня — проверка и публикация.

## Часть 2: Финальная проверка

### Полный прогон — руками, по критериям приёмки из PLAN.md:

```
[ ] Добавление: ввожу текст — задача появляется
[ ] Отметка: чекбокс — текст зачёркивается
[ ] Удаление: с подтверждением — задача исчезает
[ ] Сохранение: перезагрузка — задачи на месте
[ ] Уведомления и счётчики работают
[ ] Мобильная ширина: форма перестраивается
[ ] Консоль (F12): нет красных ошибок
```

### Независимая проверка агентом:

```text
Файлы: PLAN.md, index.html, styles.css, app.js.

Проведи финальную приёмку MVP:
1. Сверь каждую функцию из PLAN.md с кодом: реализована?
2. Найди несоответствия плану и потенциальные баги
3. Ответь: готово ли к публикации? Что мешает?
```

💡 Агент и ты проверяете независимо — это две разные точки зрения. Расхождение (нашёл то, что ты пропустил, или наоборот) — самый полезный результат.

### Последнее diff-ревью недели:

Открой в Cline итоговый список изменений проекта за неделю и пробеги глазами: всё, что в проекте, — то, что ты одобрял? Лишних файлов нет? Это финальный контроль того, что ты — режиссёр, а не свидетель.

## Часть 3: Публикация на GitHub Pages (опционально)

### Шаг 1: Репозиторий на GitHub

```
1. Зайди на github.com
2. New repository → имя: todo-app → Public → Create
```

### Шаг 2: Git через агента — с одобрением команд

```text
Инициализируй git в проекте и запушь на GitHub:
- git init, добавь все файлы
- commit: «Initial commit: MVP»
- remote: https://github.com/ТВОЙ_ЛОГИН/todo-app.git
- push в main

Покажи каждую команду перед выполнением.
```

Агент покажет команды — читай каждую перед одобрением:

```bash
git init
git add .
git commit -m "Initial commit: MVP"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/todo-app.git
git push -u origin main
```

🚨 `git add .` добавляет всё из папки. Перед одобрением проверь: в проекте нет файлов с секретами (`.env`, ключи API)? Если есть — попроси агента добавить их в `.gitignore` до пуша.

### Шаг 3: Включи GitHub Pages

```
1. GitHub → твой репозиторий → Settings → Pages
2. Source: Deploy from a branch
3. Branch: main, /(root) → Save
4. Подожди 2–3 минуты
```

Сайт появится по адресу `https://ТВОЙ_ЛОГИН.github.io/todo-app/`. Открой с телефона — мобильная версия теперь проверяется в бою.

### Если не хочешь публиковать

Приложение уже работает локально: открывай `index.html` и пользуйся. Публикация — не обязательный шаг недели.

## Часть 4: Скриншот для README

Не вставляй заглушки — сделай скриншот и добавь его в README текстовыми шагами:

```
1. Открой приложение и добавь 2–3 задачи, чтобы оно выглядело живым
2. Скриншот:
   - Windows: Win + Shift + S, выдели окно
   - macOS: Cmd + Shift + 4, выдели окно
   - Linux: PrintScreen или инструмент «Снимок экрана»
3. Сохрани как docs/screenshot.png в папке проекта
4. Попроси агента добавить в README.md секцию
   «Скриншот» с картинкой docs/screenshot.png и alt-текстом
5. Проверь: открой README на GitHub — картинка видна
```

## Часть 5: Финальный README

```text
Обнови README.md:
- Секция «Демо» со ссылкой на GitHub Pages (если публиковал)
- Секция «Как использовать» (онлайн и локально)
- Секция «Разработка»: структура проекта, AGENTS.md,
  что проект сделан через агента в Cline (Vibe Coding)
- Секция «Что я узнал» — 5 пунктов
```

### Пример финального README:

```markdown
# To-Do App

Простое и красивое веб-приложение для управления задачами.

## 🎯 Демо

Попробовать онлайн: [todo-app](https://username.github.io/todo-app/)

## ✨ Функции

- ✅ Добавление задач
- ✅ Отметка выполненных
- ✅ Удаление с подтверждением
- ✅ Сохранение в браузере (localStorage)
- ✅ Уведомления и счётчики
- ✅ Адаптивный дизайн

## 🛠️ Технологии

- **HTML5** — структура
- **CSS3** — стили и адаптивность
- **JavaScript (ES6+)** — логика
- **localStorage API** — хранение данных

## 📝 Разработка

Проект создан через Vibe Coding: человек ставит задачи и проверяет
результат, код пишет агент.

- Агент: [Cline](https://cline.bot) в VS Code
- Модели: Groq `openai/gpt-oss-20b` или локально через [Ollama](https://ollama.com)
- Правила агента: файл `AGENTS.md` в корне проекта
- План и история: PLAN.md, CHANGELOG.md

## 🎓 Что я узнал

- Планировать проект через диалог с ИИ: критерии приёмки вместо пожеланий
- Давать агенту контекст: файлы, правила, явные ссылки
- Проверять каждый шаг агента по критерию, а не на глаз
- Читать diff'ы и отклонять лишние изменения
- Восстанавливаться после ошибок: контекст + текст ошибки из консоли

---

Создано через Vibe Coding
```

## Часть 6: Ретроспектива

Запиши ответы (файл `RETROSPECTIVE.md` — попроси агента создать по твоим ответам):

```
1. Что было самым сложным на неделе?
2. Какой diff было труднее всего прочитать?
3. Когда агент ошибался — чего не хватало в контексте?
4. Что бы ты делал иначе, начни ты неделю заново?
5. Что пойдёт в v2.0?
```

Четвёртый вопрос — главный: ответ на него — твой личный ускоритель на следующую неделю.
