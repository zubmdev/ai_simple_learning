# Runbook: Telegram-канал + Threads-фидер

**Дата:** 2026-10-25. Решения: [ADR-0007](../adr/0007-bot-gateway-funnel.md). Факты и источники: [исследование 2026-10-25](../research/2026-10-25-telegram-threads-week1-funnel.md).

## Архитектура

| Кусок | Роль |
|---|---|
| Канал «AI - это просто» | Лента уроков: один пост в 09:00 Минска (06:00 UTC) |
| Группа обсуждений | Привязана к каналу; кнопка комментариев под каждым уроком |
| Бот @vibecoding_start_bot | Stateless-гейт: `/start <source>` → приветствие с кнопкой-инвайтом; каждое событие строкой в личку владельцу (личка = база данных); свободный текст пересылает владельцу |
| Threads @ai_kontur_by | Ручной фидер: один hook-пост на урок; без API-автоматизации |

## Разовая настройка

1. BotFather: создать @vibecoding_start_bot, имя и описание бота.
2. Канал: создать публичный канал «AI - это просто», добавить бота админом с правами: публикация, редактирование, приглашение пользователей по ссылкам.
3. Обсуждения: настройки канала → «Обсуждение» → привязать группу; бота — админом группы.
4. Named invite links: по одной ссылке-инвайту с именем на источник (`threads`, `github-readme`, `youtube`) — создать через клиент админа или `createChatInviteLink`. Никогда не пиши в кампаниях голую ссылку `t.me/<канал>`: она не даёт атрибуции.
5. Переменные окружения (локально в `.env`, в GitHub — Secrets: `BOT_TOKEN`, `CHANNEL_ID`, `OWNER_CHAT_ID` нужны обязательно; `DISCUSS_URL` — опционально):

   | Переменная | Кто читает | Зачем |
   |---|---|---|
   | `BOT_TOKEN` | publisher, bot, snapshot | токен BotFather |
   | `CHANNEL_ID` | publisher, snapshot | `@юзернейм` или `-100…` канала |
   | `OWNER_CHAT_ID` | bot, snapshot | личка владельца — куда пишутся события |
   | `REPO_URL`, `REPO_BRANCH` | publisher | ссылки «Урок на GitHub» и приложенный исходник |
   | `DISCUSS_URL` | publisher | необязательная кнопка «Обсудить» |
   | `CHANNEL_INVITE_URL` | bot | кнопка-инвайт в приветствии (named link) |
   | `WEBHOOK_SECRET` | bot | произвольная строка `A-Za-z0-9_-` (1–256) |

6. Хостинг бота: любой free-PaaS. Запуск — `python3 -m pipeline.bot --serve` (порт берётся из `$PORT` или 8000). Затем один раз: `python3 -m pipeline.bot --set-webhook https://<домен-paas>/webhook`.
7. Проверка гейта: открыть `https://t.me/vibecoding_start_bot?start=threads` → в боте приходит приветствие с кнопкой канала; в личке владельца появляется строка `🚀 /start source=threads — <имя>`.
8. Threads: в приложении убедиться, что хэндл @ai_kontur_by доступен и закреплён за нами (A5, [HUMAN CHECK]). Токены/разработчикское приложение Threads не нужны — постим руками.

## Ежедневный цикл

Автоматически:

- 06:00 UTC — GitHub Actions `publish` берёт из [launch/schedule.tsv](../../launch/schedule.tsv) строку с сегодняшней датой (UTC) и статусом не `done`, публикует урок (пост с кнопками на первой части + приложенный `.md`) и помечает строку `done` — `github-actions[bot]` коммитит изменение расписания.
- 08:41 UTC — повторный запуск `publish` как страховка: если утренний прогон упал, он опубликует и пометит `done`; если строка уже `done` — ничего не сделает.
- 06:30 UTC — `snapshot` дописывает число подписчиков в `docs/metrics/subscribers.log` и шлёт дельту в личку владельцу.

Вручную (10–15 минут):

1. Hook-пост в Threads по уроку дня (шаблон ниже).
2. Ответить на все реплаи: персональный указатель + карточка на канал (named link `threads`).
3. Разбор лички владельца: новые `🚀 /start` (источники), `🎚 опыт`, пересланные вопросы — ответить каждому в боте.

Шаблон hook-поста (≤500 знаков, один тег, ≤5 ссылок):

> <проблема из урока, 2–3 предложения, живым языком>
> Напиши в ответах, что хочешь собрать или где застрял, — отвечу персонально. Весь курс бесплатно в Telegram → карточка ниже.
> #айдишник

Правила: карточка канала либо в посте, либо первым ответом (A/B); консультации в Threads не продаются — только внутри Telegram (ADR-0004).

## Еженедельно

Свести воронку в одну таблицу: Threads (просмотры / реплаи / клики) → t.me-старты по source (ручной подсчёт `🚀`-строк в личке владельца за неделю) → подписчики (`docs/metrics/subscribers.log`) → просмотры постов дня. Ноль inbound четыре недели подряд → kill Threads (план §6).

## Аварийные процедуры

- **Опубликовать сейчас, вне расписания:** Actions → `publish` → Run workflow → в `files` указать путь, например `ru/beginner/Week_1/Day_2.md`. Или локально: `python3 -m pipeline.publisher --publish ru/beginner/Week_1/Day_2.md`. Ручной запуск **не трогает** расписание: если опубликовал строку из `launch/schedule.tsv`, сразу поставь ей `done` и запушь (или запусти локально с `--mark-published` и закоммить), иначе retry-cron в 08:41 UTC опубликует её повторно.
- **Утренний cron не сработал:** ничего не делай — в 08:41 UTC retry-cron опубликует сам. Чтобы не ждать, запусти `publish` вручную с пустым `files` (возьмёт сегодняшние строки не-`done`, но не пометит их — см. пункт выше).
- **Изменить расписание:** отредактировать `launch/schedule.tsv` и запушить; cron читает файл в момент запуска. Строки со статусом `done` не публикуются повторно.
- **Двойная/кривая публикация:** удалить пост в канале вручную, перезапустить `publish` с нужным файлом; перед этим проверь, что строка в `launch/schedule.tsv` помечена `done`, иначе cron её повторит.
- **Бот лежит:** новые читатели всё равно заходят в канал по поиску/обычной ссылке — страдает только атрибуция. Поднять сервис на PaaS, при необходимости повторить `--set-webhook`.
- **Токен утёк:** BotFather → `/revoke` → обновить `BOT_TOKEN` в GitHub Secrets и на PaaS.

## Что где лежит

- `pipeline/bot.py` — гейт; `pipeline/snapshot.py` — снимок подписчиков; `pipeline/publisher.py` — публикация уроков; тесты — `python3 -m unittest discover -s pipeline`.
- `launch/schedule.tsv` — календарь публикаций (даты в UTC; 5-я колонка `status`: `todo`/`done`, `done` не публикуется повторно).
- `.github/workflows/publish.yml`, `.github/workflows/snapshot.yml` — кроны publish 06:00 и 08:41 UTC, snapshot 06:30 UTC.
